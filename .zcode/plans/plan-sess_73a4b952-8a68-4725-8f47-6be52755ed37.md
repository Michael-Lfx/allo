# 学习图重构：跨课程概念图（生长式）实施计划

## 已确认的决策（grilling 结论 + 档位修正）

| 决策点 | 结论 |
|---|---|
| 旧"学习图"（course_kind='learning_graph'，DAG 版） | **代码+UI+数据彻底删除** |
| 依赖模型 | **纯概念网，无先修边**：节点 teaches/assumes 概念；就绪 = assumes ⊆ 全局已教概念集（跨课程）；**UI 无锁定态**，不可执行的节点由结构门/AI 评审打回，永不发布 |
| **概念档位（本轮修正）** | **引入三级档位：知道 / 会用 / 能教**（en-US: Know / Apply / Teach，i18n 双语键）。teaches/assumes 均携带档位；**就绪判定与结构门做档位比较：节点的每条 assumes(concept, 档位) 必须被某节点（含同批兄弟）teaches 同一概念且档位 ≥ 所假定档位**。不满足 = 整批打回重裁，而不是入库后锁定——"发布即就绪"是硬不变量 |
| 生长 | 就绪节点 **< 3 触发**（节点完成时自动检查）+ 课程页手动按钮；每批 ≤7 个新节点，**补到 7 个就绪**；结构门 + 一次 AI 概念评审，**自动通过、无提案收件箱** |
| 终点锚（多终点） | 建课时 **AI 提议 1-3 个 + 用户可编辑**；课程内随时手动增删；终点变更 → **自动重画罗盘**；罗盘在课程页**默认收起、点击展开**，同时作为生长上下文；终点是纯标记节点（无正文无题目），教练可裁决完成 |
| 概念登记表 | **新建全局表**（跨课程唯一，canonical+别名）；传统课程 learning_concepts 体系**代码+UI+数据全删**（题目绑概念入口、概念掌握度展示、/api/learning/concepts、判卷 prompt 中的概念依据全部退场；判卷退化为按题目本身判分，**单节点完成标准不变**：手动申报完成、作答 ≥0.6、reflection/open_question LLM 判卷、完成后种 FSRS 卡） |
| UI 命名 | **沿用"学习图 / Learning Graph"**；图谱界面（DAG 画布）删除，改为**双 Tab：学习记录（按批次时间线）+ 概念表** |

不在范围（勿误伤）：nomi 伴侣 LearningGraphTab、conversation/workshop 的 xyflow 使用（`@xyflow/react` 依赖**保留**）。

### 2. 后端：删除与替换（`crates/backend/nomifun-learning/`、`crates/backend/nomifun-ai-agent/`）
**删除**：`learning_graph/draft.rs`、`audit.rs`、`review.rs` 及 `mod.rs` 中 DAG 符号内核（~3500 行）；`service/learning_graph.rs` 中 draft/审计/发布逻辑；`nomifun-ai-agent/src/learning_graph_loop.rs`（DAG 生成循环；SCOPE_SYSTEM 保留改造复用）；models 中 `Graph*View/LearningGraphGenerationStatus/ResumeLearningGraphRequest` 等。

**新建 `learning_graph/growth.rs`（或同目录新模块）**：
- **就绪计算（档位感知）**：`ready_set(course)` = 本课程未开始的非终点 lesson，其每条 assumes(concept, tier) 都存在某节点（任意课程）teaches(concept, tier') 且 tier' ≥ tier（know<apply<teach 偏序，结构口径、不看掌握度）；终点标记 lesson 永不进列表。
- **结构门（apply 前确定性校验，违反即整批拒回）**：批内自足（assumes 只能指向已满足档位的概念或本批兄弟 teaches）；**档位反查**（引用概念必须在登记表或批内铸名，且档位覆盖成立）；铸名合法（canonical/别名与全库不撞）；终点保护（不可新增/改/删终点节点）；标题课程内唯一；≤7 个 add_node。
- **AI 概念评审**：单次 `LearningCompleter` 调用（挂号/前提档位足够/命名一致），输出 JSON verdict；reject 带问题清单回灌一次重裁（沿用旧 repair 模式），再失败则整批放弃并报错。
- **教练生长循环**：`learning_loop.rs` 五插头外壳 + `one_shot.rs` 白名单工具（`lg_roster/lg_patch/lg_finish`）；prompt 输入=课程目标+罗盘+花名册（概念+档位+状态）+逐终点覆盖读数+登记表相关切片+**档位定义**（知道=能辨认复述，会用=能解题应用，能教=能讲解纠错）；结束条件="把就绪补到 7 个"；apply 后写 `learning_growth_batches` + WS 进度帧。
- **触发器**：lesson 完成申报处（`service/progress.rs`）计算该课程就绪数，<3 且无进行中生长任务则入队（复用 generation_registry + 每课程 slot 串行）；手动按钮走同管道强制入队；建课完成即首生长。
- **罗盘**：终点增删改 → 入队单次 LLM 重画 → 落 `compass_md`；生长时若无罗盘先生成。

**内容生成适配**：`service/lesson.rs` 的 `render_prerequisite_path`/`render_forbidden_descendants`（:1459-1520）从先修边改为概念网口径（assumes 概念+档位、教它们的节点摘要、下游假定本课概念的节点=禁止提前讲授清单）。

**判卷去概念化**：`service/progress.rs` 的 `REFLECTION_GRADING_SYSTEM`/`OPEN_QUESTION_GRADING_SYSTEM` 删除绑定概念依据段；删除 mastery EMA 写入（`progress.rs:561-601`）与 `review.rs` concept_refs。

**传统概念体系删除**：`routes.rs` 的 `/api/learning/concepts`；`service/course.rs` 大纲导入的概念落库段；`course_outline_loop.rs`/blueprint prompt 中概念产出契约；models 清理。

**路由**：保留 `POST /courses/generate`（graph 分流改为"建课+终点+首生长"）、`/generate/status|cancel`；新增 endpoints CRUD、registry 概念表查询、学习记录（批次+节点历史）查询、罗盘重画触发。
