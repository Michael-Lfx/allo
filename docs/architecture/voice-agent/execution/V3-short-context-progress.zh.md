## 问题和修复

前端最近三轮阅读记录已有实现，但生产worker调用 `route_with_output` 时没有更新router短历史。读取面板历史也不足以修复：面板加入当前转写轮次后已经淘汰第三个历史轮次，且结束会话后文字须保留，推理历史须清空。

在既有daemon会话投影内保存独立的最多三次已完成聊天交换，传入现有VoiceRouter上下文接口；OpenAI-compatible/Flowy HostDialogueClient路径都复用router已有短历史装配，仍每轮一次模型调用。上下文是请求显式输入，模型适配器不在多次请求间保存可变会话状态，不初始化任务runtime或添加数据库。

仅有效聊天回答加入历史；会话结束、失败Idle和新唤醒清空推理上下文，阅读记录保持原来最近三轮。没有将模型完整JSON、未真实接受的任务ACK或错误提示当成助手历史。TTS失败/关闭时有效文字回答仍属于当前会话。
