## Question

learnhub #88 立了全系统量纲宣言（用户定调，两轮修正后终稿）：**1 XP = 1 est 分钟 = 1 分钟
专注学习**；量纲一元、来源多元（est 按 1 est 分钟 = 1 XP 计价仅为「完成学习点」一种来源，
复习/quiz/奖励各有定价，按同一量纲入同一账本）；XP 记努力账不记掌握（进度 = 结算数、
掌握 = 证据回放聚合，两把尺严格分离）；est 是尺寸锚（出生即铸、内容层继承）；est 感知面
定位不变（不进门禁、不进调度、不得变成日程）。

allo 现状（对照见 assets/r2 §5）：**三套量纲互相独立无桥**——教练 minutes（1-60 门、提示词
常规 5-30/极困难 60、缺省 10 落 estimated_minutes）；打卡按复习事件计数（缺省 15，与分钟
零换算）；XP 在 companion crate（Lv=sqrt(xp/100)，伴随对话每轮 +2），学习模块零 XP。

需要裁决：

- **(a) 全域采纳**：学习模块宣言 + 桥到结算（完成节点/打卡 → 按 est 计价入 XP 账本，
  companion XP 语义统一或新立学习结算账）。
- **(b) 学习模块内采纳**（轻）：术语与语义统一（minutes 即 est 专注工作量、内容层继承、
  不进门禁不进调度），CONTEXT.md 立词条，教练/内容提示词措辞对齐；**不碰 companion XP、
  不新建账本**——XP 桥属跨模块产品决策另议。
- **(c) 不采纳**：维持现状（minutes 只是字段名，无宣言），本轮跳过量纲题。

连带面：若 (a)/(b)，`minutes` 字段是否更名 est/est_minutes（DB 列 070 风格 append-only，
更名成本）；打卡口径是否挂量纲（现为事件计数）；(a) 还需定结算点与防刷规则（完成即结算？
重复完成？跳过的计价——learnhub 跳过是否计 XP 需回查）。

约束：est 感知面边界照抄（不进门禁、不进调度、不得变成日程——一轮「深度水位门退役」已与
此精神一致）；若 (b)，明示「allo 无 XP 账本，宣言是前瞻预留」。
