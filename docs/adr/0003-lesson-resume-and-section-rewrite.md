# ADR-0003: 课时生成断点续跑与节级单节重写

Status: Accepted

Date: 2026-09-08

## Context

迁移 050 的注释承诺了节状态（pending/ready/failed）"支持断点续跑与单节重写"，但服务层
两者皆无：

- **续跑**：课时内容循环（`lesson_content_loop`）没有 resume 入口——生成失败或超时后
  草稿虽保留（错误消息里写着 "draft survives"），重试却从零重建一个全新草稿；草稿存储
  纯内存且无 TTL（与学习图草稿的 1 小时 TTL 不一致）， abandoned 草稿泄漏内存。
- **单节重写**：不存在任何 section 级路由；某一节质量不佳时只能整课重生成（浪费全部
  已通过的节，题目一并重建）。
- **visual 承诺不落库**：大纲声明的本节可视化形态（公式/函数图/示意图/流程图/图表/
  表格/无）只活在生成期草稿——质检门按它做承诺兑现检查后即丢弃。没有这个持久事实源，
  单节重写无从按原声明兑现质检。

参照 learnhub 的对应机制：节清单持久在 frontmatter，是逐节生成进度的事实源；重跑跳过
已 ready 的节；单节可独立重写并复检（`learnhub_content_check`）。

两个项目的 agent loop 形式不同，learnhub 的机制不能照搬：learnhub 的内容生成是 host
确定性管线（逐节循环是 host 代码，"跳过已 ready 节"是免费品）；本项目是引擎化两轮
agent 循环（生成循环 + 审计门驱动的修复循环），续跑必须以**模型可见的方式**恢复认知。

## Decision

**续跑（Resume）**：

- `LessonGenerationContext` 增加 `lesson_id`；服务层维护 `lesson_id → draft_id` 内存
  映射。生成失败后草稿在 TTL 内存活时，重试同一课时经映射定位草稿，走引擎的
  `resume` 入口续跑；无存活草稿则全新生成。复用现有
  `POST /api/learning/lessons/{id}/generate` 端点，不新增 resume 路由——课时不存在
  "完成后继续"的语义（学习图的显式 `/resume` 是因为图可以生成完成后继续扩建）。
- 循环形式下的认知恢复：与学习图循环同构——每轮的意图（工具摘要 + 计划文本）记入
  轮次日志；续跑时草稿当前状态 + 上次会话轮次日志注入开场 user 消息（"接着此进度
  继续，不要重复已写好的节"）。已写的节就在草稿里，模型重复写即整节替换，浪费可
  见但无损正确性。
- 草稿存储带 1 小时 TTL（惰性清扫，patch 刷新活跃时间），与学习图草稿对齐；发布
  成功即清除草稿与映射。
- 迁移 050 的注释承诺由此兑现，注释无需修改。

**单节重写（Rewrite）**：

- 走**确定性单节管线**（`rewrite_section_body`：一次有界调用 + 定位修复 + 节级质检门
  + visual 降级兜底），不走 agent 循环——单节没有规划需求（节清单已在节表），门禁
  全是确定性校验，循环的多步自主价值用不上，一次有界调用更省更稳。这与"生成走
  loop、修补走管线"的 learnhub 分工哲学一致。
- 迁移 051（append-only）：`learning_lesson_sections` 增加 `visual TEXT NOT NULL
  DEFAULT ''`；生成落库时写入声明。`''` 为历史行的"未声明"，质检按保守口径（要求
  任意可视化块）处理，不改写历史数据。`SectionView` 同步暴露 `visual`。
- 新路由 `POST /api/learning/lessons/{id}/sections/{key}/rewrite`：原地更新目标节
  （`version+1`），其他节与题目不动；`summary` 由全部节重新拼装（双读回退文本同步）。
  单事务保证节更新与 summary 拼装同生共死。
- 上下文与生成路径同口径分流：传统课时注入概念黑名单 + 引用摘录；学习图节点注入
  前置已教摘要 + 下游节点禁止清单（复用 `graph_node_topology`）。

## Consequences

- 生成失败的重试成本从"整课重来"降到"从中断处继续"；大课时（高复杂度 6 节）的
  失败浪费显著缩小。
- 节级修复成为可暴露的产品能力（后端先行，前端按钮后置）；`visual` 落库后单节重写
  的质检承诺与初次生成一致。
- 轮次日志与草稿同为内存态：进程重启后续跑不可用（重试即全新生成）——与学习图
  续建的一致取舍（本地优先应用，持久化任务系统不值得）。
