## 1. 固定目标与当前状态

完成离屏用户能判断“可以说话→识别完成→处理等待→真实回复→追问→结束/失败”的流程；同时保持连说、低音量、停止、正文及真实任务边界。

用户已选择轻量反馈。参数初值由PRD冻结供测试：倾听中点一次提醒，处理第3/9/15秒最多三次，讲话或播放期间撤销低优先级音。按Owner听辨与回声证据调整音色/响度，不修改原六秒、四秒、三十秒和授权上限。

## 4. 验证梯子

1. R0先执行当前Q/P生产worker回归，保存基线；随后新增本片失败测试。已有标准音频留用，按时间轴添加提示音回收与混合样本。
2. 受影响 `nomifun-audio`、`nomifun-voice-terminal`、`ai-mate`、`nomifun-app` 分别跑行为测试/编译；涉及宿主的用例同时包含完整桌面feature图，复现并防止Q的TLS组合回归。
3. 定向前端行为与中英文断言、i18n生成/检查、theme、相关CSS与按钮门禁，typecheck。
4. 集成运行Rust格式、`cargo check --workspace`、`bun run check`、`bun run build:ui`、宿主/daemon生产构建。既有60个非语音类型错误独立记录；没有跑或失败的全仓门禁不能标通过。
5. 检查生产feature图不带voice-skeleton。在线Edge和固定真实provider探针显式执行；标准音频全链允许测试模型，但报告区分模型替身/真实模型、输出替身/物理扬声器。
6. Owner已负责实机验收；除非获得新的启动/录音/播音授权，不自动启动设备。更新默认程序须Owner退出、检查实际进程、同时替换宿主/daemon、核对SHA256并留回执。

本轮是文档变更，不跑业务构建来伪造新增声音能力已验证；完成文档链接、编号覆盖、参数/策略一致性、历史正文与diff空白检查。

## 5. Owner离屏剧本

1. 学习声音含义后遮住面板：唤醒、保持静默听中途提醒、再听休眠；明确区分“本轮结束”与“功能关闭”。
2. 连说唤醒词与完整问题；提醒将响时用普通/偏轻音量开口，核对没有首字丢失、漏收或自己被提示打断。
3. 正常问候和慢回复分别执行：识别音一次，慢处理轻音有上限，回答不夹杂等待音；听到追问提示后近四秒再说完整句。
4. 分别停止合成、回复与提示，接着再次唤醒；确认没有旧声音突然出现。主动停止短音是约定反馈，不算旧TTS残留。
5. 故障/静音/输出拔插/网络断开，确认不永远滴答、文字保留且设备恢复不补播旧音；注意扬声器故障不能靠声音告知。
6. 接runtime后另测真实接受/拒绝、任务完成不插话、取消终态、实际危险操作确认/拒绝/超时。当前截图只证明拒绝文案，不能签核任务已经执行。

记录Windows设备型号、默认输入/输出、系统音量、应用音量、人与设备距离、噪声环境、语言、主题及每个用例结果。建议先电脑前、约一米、约两米分别测；这是测量条件，不是产品已承诺的有效距离。不编造用户规模或听辨准确率。Linux/macOS及无屏硬件以后按同剧本另行验证。
