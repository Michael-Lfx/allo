## 1. 摘要

语音伴侣仍是独立声学进程与桌面宿主共同提供的产品入口，使用既有模型服务完成聊天，使用既有 runtime 完成真实任务。本版将“看屏幕能用”推进到“人在电脑旁做其他事，也能凭声音完成短对话”。

用户已反馈 KWS → ASR → LLM → TTS 基本链路正常。当前缺口是听取、识别、等待、追问及结束反馈不完整；任务 runtime 仍未接通。这两件事分别验收，补提示音不能被写成任务已可执行。

## 3. 背景与事实基线

### 3.1 已确认的需求

用户希望补齐唤醒后的持续状态感、ASR 结束识别音、休眠音等离屏场景，并重新制定 PRD。用户进一步确认采用：进入倾听时响一次、未开口中途提醒一次、处理较久时轻音反馈、讲话与播报期间暂停；不采用持续背景音。

### 3.2 代码核对结果

| 现有事实 | 缺口与影响 | 本版要求 |
| --- | --- | --- |
| 六个内嵌 PCM WAV：wake 20ms、guide 60ms、alert 100ms、done 120ms、sleep 60ms、error 80ms | 有文件并不代表所有出口都播放；可听性也未单独签核 | 用真实状态驱动，做离屏听辨与输出验收 |
| 接受 wake 会发 Listening 并播放 Wake | 入队结束不等于声音结束；六秒计时当前在声音完成前启动 | 有效听取时间不被提示音占用，保留连说指令 |
| 无意图/空结果路径已有 Sleep，任务未接通路径有 Error | 六秒静默、四秒追问超时和主动停止缺少完整声音出口 | 按结束原因分别反馈，避免错误音与休眠音连响 |
| ASR 有 SpeechRecognized，模型、合成及播放有阶段快照 | ASR 成功及长等待没有听觉反馈 | 识别成功音与处理轻音；不得伪装真实回复 |
| TTS 使用真实 Edge；回复文字在失败后保留 | 输出失败时只有文字，离屏用户不知道交互为何中断 | 本地失败提示、可播放时的固定原因短语、明确降级 |
| play_earcon 当前只写入输出端，调用点多数忽略返回错误 | 无法区分“计划响”“输出成功”“设备失败” | 完成/失败/取消可观察，不能假称用户听到了 |
| daemon 统一声学消费，宿主共享快照，UI 不负责录音 | 多窗口可能诱发重复反馈，提示音还可能被麦克风收回 | daemon 唯一发声者，作用域去重与回声回放门禁 |

证据位置和行号见配套技术方案；WAV 时长由本机读取实际头部得到。已有文档宣称 CC0，不代替新增/修改资产的许可核对。

### 3.3 验收状态

用户的基本链路反馈作为 Owner 定性试用证据记录，不扩展成全部 AC、准确率、延迟或三平台通过。Q 轮测试证明完整桌面 TLS 修复、真实声学回放及在线合成；其中模型和输出消费使用替身，见 [Q 报告](execution/Q-full-flow-tts-closure.zh.md)。本版新增 AF 验收目前全部未执行。

## 4. 目标与成功标准

| 目标 | 发布验收方法 | 要求 |
| --- | --- | --- |
| 不看面板也能完成聊天 | 遮住面板，执行唤醒、静默提醒、识别、慢等待、回复、追问、休眠与失败脚本 | AF-AC-01–12、15–16 全通过；Owner 能判断现在该说话、等待还是结束 |
| 声音不破坏识别 | 同一标准语音在提示音开/关下回放；再做扬声器至麦克风实机测试 | 已有正样本指令不丢首字、每轮模型一次、零输入溢出；提示音不能产生新命令 |
| 状态与后台事实一致 | 停止、重连、任务拒绝、延迟/重复回执及确认过期测试 | 不补播历史声，不播假接单；任务接通后另过 AF-AC-13–14 与原 AC-11–17 |

声音设计必须通过两个不同门禁：数据到达输出端，以及实际能听到且不刺耳。现有唤醒首音目标 ≤200ms 继续保留；新增阶段事件到提示音开始目标 P95 ≤200ms，仅统计无更高优先级音频且设备可用的事件。记录设备、距离、音量、样本量和起止点；未测不得宣称达标。

## 5. 用户与场景

| 用户 | 要完成的事 | 主要约束 |
| --- | --- | --- |
| 在电脑旁整理物品、看纸张或操作其他应用的人 | 说一句问题、知道听取是否开启、听完再追问 | 不看屏幕，声音必须有清晰边界；不能持续干扰 |

无屏部署可复用 daemon 声音规则，但不因桌面通过而自动签核无屏硬件。人在外地通过音频远程控制、不在麦克风有效范围内、多人共享和全双工打断仍不在本期范围。

## 7. 产品方案

### 7.1 完整旅程与不变规则

1. 下载声学套件、检查设备和已有 provider 模型；用户明确启用后才采集。模型就绪不会自动录音。
2. 唤醒成功响一次进入倾听音；窗口同步显示可说话。用户可以连说指令，不必等声音结束重说。
3. 六秒有效听取内尚未开口，在中点轻提醒一次；已经开始讲话就取消提醒与启动倒计时。句子最多三十秒，停顿后整句 ASR。
4. ASR 原文立即显示；非空且去除唤醒词后仍有内容才响识别成功音。模型同一次调用返回“理解的需求”和回答，不额外请求模型生成提示语。
5. ASR/模型/合成合计等待较久时，按下表稀疏轻音提示仍在处理；等待音不表示成功，也不表示正在倾听。
6. 回复使用真实 TTS。播放完成后响一次追问开启音，音结束后的四秒用于开始说话；期间讲话可以说完，不能在第四秒截断。
7. 未继续讲话，响一次休眠音，结束本轮，保留文字。唤醒监听是否继续由功能启用状态决定，后台任务不因关窗/休眠取消。
8. 任务当前不可用时说明“任务执行尚未接通，我没有提交这个任务”；以后只有真实 Accepted 才播接单，确认、取消和完成同样遵循回执。

保留 Windows 先完整交付、Linux/macOS 结构兼容及独立验收；继续使用独立 ai-mate、现有 provider/TtsProvider 和已有 runtime。沿用三个阅读轮次及原短上下文要求；阅读记录不等同于模型已收到三轮历史。

### 7.2 声音规则表

以下时间/音量是实施初始参数，须经听辨和回声测试；调整留下证据，不暗改六秒、四秒、三十秒或确认授权上限。

| ID / 场景 | 用户理解与声音 | 触发及次数 | 计时/抑制规则 |
| --- | --- | --- | --- |
| AF-01 就绪 | 自检完成；Guide 家族短音 | 用户主动启用/修复成功一次 | 不在每次心跳或应用自动恢复时反复播放 |
| AF-02 唤醒/手动开始 | “可以说话”；Wake | 成功接受会话一次，两入口相同 | 先开始采集与保留预滚；未开口时六秒从提示音完成算起，已开口不再启动期限 |
| AF-03 倾听提醒 | “我仍在听”；轻量 Wake 变体 | 有效听取第三秒、仍未开口时一次 | 最近至少500ms安静才允许发声；任何人声候选出现即撤销。提示音 ≤120ms，六秒有效窗口不被播放占用 |
| AF-04 识别成功 | “这句话识别到了”；Guide 家族的识别短音 | 有效 SpeechRecognized 一次 | ASR 空结果、纯唤醒词不响；不表示模型理解正确或任务已接单 |
| AF-05 等待处理 | “正在处理”；低音量双轻音 | 句末处理开始后第3/9/15秒，整轮最多三次 | 跨 ASR/模型/合成共享次数，不随阶段重置；模型/合成结束或声音已开始立即取消，不延长任何请求超时 |
| AF-06 回复 | 助手真实回答 | 原文、理解、回复均展示；仅播用户可理解正文 | 不朗读 JSON；第一帧写入才显示播放中；处理中不承诺能识别口头打断 |
| AF-07 追问开启 | “可以接着说”；Wake 家族变体 | 回复实际消费结束，或TTS失败进入可收音的文字追问时一次 | 结束音本身不是追问音；追问音完成后起四秒，已开口则不再设开始期限。文字追问只在输出仍可用时响，说明文字已保留 |
| AF-08 正常休眠 | “这次听取结束”；Sleep | 初次六秒/追问四秒静默、无意图正常结束一次 | 按退出原因统一去重；播放期间不接收新任务，仍允许显式再次唤醒取消旧尾音 |
| AF-09 停止/关闭 | “已停止本轮”；Sleep 短音 | 用户停止或关语音窗一次 | 先停推理/TTS并 flush，再可选短音；用户关闭全部声音时零音频；完全退出/关功能不强制尾音 |
| AF-10 错误与降级 | “这轮未完成”；Error，加可用的固定原因短语 | 一次错误簇最多一个错误音 | 同轮错误退出不再紧接 Sleep。错误音本地离线；TTS故障不递归调用同一故障TTS，扬声器坏不能声称已提示 |
| AF-11 任务接受/结果 | 接单正文；Done 或 Error + 真实摘要 | Accepted 后一次 ACK；完成通知按任务终态去重 | 当前在听/说/确认时延后；恢复旧任务不重播新接单；运行期间不周期滴答 |
| AF-12 工具确认 | Alert + 实际动作/影响 + 明确询问 | 当前 call 一次，每次重新询问有独立身份 | 提示及开启音播完才开始听，最多八秒且不超过runtime有效期；过期拒绝，不用声音替代授权 |

默认进入、识别、退出短音单次20–180ms，等待双轻音总长≤250ms；是否沿用/组合六件资产由听辨测试决定。不为了凑数量给所有状态各造一种音色。音量以数字增益控制而非声压承诺：标准短音初始约 -6dB、提醒/等待约 -12dB，相对于素材幅度；实际响度取决于系统和设备，不冒充物理 dB SPL。

**原因短语**使用本地固定双语文案，交给现有 TTS，零额外 LLM 请求。例如模型失败“对话服务连接失败，请稍后再试”、任务未接通“任务执行尚未接通，我没有提交这个任务”、空识别“没有识别到内容，请再说一次”。TTS不可用时仅本地错误音与保留文字，离屏用户得到“未完成”的信号；离线逐字说明需要将来另外批准的本地短语资产或 TTS 能力，本版不假定已经具备。

### 7.3 提示模式与面板

- 设置“声音反馈”：轻量（默认）、必要提示、关闭提示音。必要提示保留唤醒、识别成功、追问、正常结束和错误，关闭中途提醒及长等待音。提示音关闭不关闭助手TTS。
- 独立“播报回复”开关，控制回答、固定原因说明和任务/确认语音说明；关闭时文字可用，UI说明离屏能力受限。两个开关均关闭时不会有任何音频；危险任务确认不因此放行，提示无法完成时不接受口头批准。
- 提示音音量0–100%，只作用提示音；0等同静音。设置试听六类语义，用户可学习含义；试听不触发 wake、录音、ASR或任务。播放失败明确显示输出设备原因。
- 默认语种沿用应用 zh-CN/en-US；状态音无需语言，固定原因短语双语。保持现有模型选择，不在声音设置再存 key 或模型副本。
- 活动面板与窗口同步呈现：当前阶段、何时可说话、倒计时、输入量、ASR原文、理解、回答、任务真实状态、停止与再次开始。完整模型输出折叠，面向调试。
- 诊断显示最近一次声音的类型、等待/开始/完成/失败/跳过以及理由。已输出不等于用户听到；重连后显示历史状态，绝不重放历史音。

本期保留半双工。仅在 Listening、FollowUp 或经授权的 ListeningConfirm 接受当轮语音；处理中/播报中不承诺“说停就打断”。按钮停止和再次合法唤醒的现有边界继续有效；离屏全双工与全天候口头打断需要独立方案，本版不借增加提示音宣称具备。

### 7.4 安全、干扰与可用性

1. 声学与声音调度不能被 renderer 生命周期控制；离开设置、隐藏托盘继续按daemon真实状态反馈。
2. 单个有效输出通道，短音与 TTS不混播；停止优先，任务通知不能插话。
3. 持续消费麦克风，不能通过静音整段录音或暂停worker来避开自己发出的音效；连说、提示音期间开口、低音量及迟开口均要回归。
4. 提示音误入麦克风可能影响VAD/KWS/ASR，这是当前没有全双工AEC时的发布风险；实机未证明无污染，不发布离屏增强模式。
5. 静默被正常收音但无人讲话是正常Sleep；无PCM、设备故障、ASR空、模型失败、TTS失败是不同错误，不一律声称休眠成功。
6. 固定原因短语一次尽力播放；失败不重复重试或触发另一条声音错误循环。回复文本和具体错误始终保留。
   TTS失败而扬声器仍可用时，本地错误音后可以响追问开启音，四秒听取从该音完成算起；输出端已失效时不等待不可能到来的声音回执，使用明确文字追问期限，不宣称离屏仍可用。
7. 不新增默认录音保存；日志只记录事件身份、音类型、耗时、数量及脱敏错误，不记用户正文、凭据或完整敏感任务参数。
8. 不播放 LLM 生成的 spoken_ack 来证明任务成功。危险操作确认必须说明真实动作、对象和范围，噪声/模糊应答/过期均拒绝。

| AF-AC-10 | SSE重连/快照重发/daemon重启/换用户 | 历史音不重播，旧timer撤销，身份隔离；独立窗口无声音第二来源 |
| AF-AC-11 | 轻量/必要/提示音关、回复关、音量0，双语双主题 | 音频输出数量符合设置；显式试听不启动录音；危险确认不因静音自动批准 |
| AF-AC-12 | 六件音效及固定短语，经扬声器回到麦克风；含连说/低音量语音 | 音效本身不创建语音请求，真实指令保持一次；真实输出回声不得触发新任务 |
| AF-AC-13 | runtime拒绝/接受、任务完成于用户讲话时、重复终态 | 拒绝不ACK；Accepted才ACK；结果延后且一次，恢复不重播；原AC-11–13/16–17同时通过 |
| AF-AC-14 | 实际工具挂起，播完确认/拒绝/静默/过期/错call | 动作说明真实，听取期限正确，授权只有一个权威；原AC-14–15同时通过 |
| AF-AC-15 | 遮住面板按完整正常/失败剧本实测 | Owner能辨识可说话/识别完成/等待/追问/结束，能听清且不刺耳；记录距离、设备、音量 |
| AF-AC-16 | 最小化、托盘、断线恢复、安装后退出 | 不依赖设置页面，有且只有一个发声者；安装资源可用，应用退出无残音/子进程残留 |
