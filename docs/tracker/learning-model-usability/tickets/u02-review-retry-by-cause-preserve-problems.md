# u02：评审失败不再连坐，降级不再吞掉已发现的问题

## 问题与证据（审计②#1#2，证实）
- concept_review 重试缝恰一次、各面共用（mod.rs ~:1512-1546）：run-1793951137445 第 3 轮评审先超时（「json coach call exceeded 480s」）用掉唯一重试，重试回包挂号表一处措辞未逐字 → 直接降级。
- 超时重试与违约重试共用纪律句「修正上一轮回包的违约处…其余裁决保持稳定」——超时根本没有回包可改。
- 降级（degraded_outcome / review_unavailable_outcome）把 problems 清零：run-1793859632428 吞掉 6 条硬伤、run-1793951137445 吞掉 1 条合法 reject，两批带已知缺口落库。

## 实施要点（机械/纯增量，不挂开关）
- [ ] concept_review 循环：**传输类失败（调用 Err：超时/网关/流中断）另计一次重试额度**，不占挂号表/碎片/契约违约的那一次；二者都用尽才降级。
- [ ] 传输类重试的 feedback 用独立话术：「上一轮评审调用失败（{error}），没有收到回包——请完整重新评审本批」；违约类沿用现话术。face_note 分支相应加臂。
- [ ] 降级保全：记录最后一次**成功解析**的 verdict 的 problems；降级时把它们逐条写进 findings（field=`review_problems`，issue 以「降级前评审已提出：」开头，保留 node/advice），批次 note 追加「降级前评审提出 N 条问题，已转 findings 留痕」。**不改放行语义**（不新增阻断）。
- [ ] 新测：超时→违约（各一次）仍能救回；超时两连→降级；降级时 problems 转 findings；违约路径话术不变。

## 三件套
- **主指标**：评审降级率（降级次数/评审轮）；降级时 problems 留痕数。基线：r01 第二跑 1/2 轮降级且 1 条 problem 丢失。
- **护栏**：r01 全部测试、挂号表/碎片面既有测试全绿；放行/打回语义不变；传输与违约各恰一次重试（最坏每轮评审调用 +2）。
- **推翻条件**：无（机械增量）；若真机每轮评审调用次数中位数上升 >1 需复查分账是否误触。
