## Question

learnhub #102/#112 的课程管理裁决：「现存且启用」（`active_course_ids` 单源——目录在场
∧ enabled，条目缺席 = 滞后合法视为启用）作为读侧横切口径：**安排面全收窄**（到期队列/
教新候选/quiz 覆盖/进度尺分子分母/自由练习），**历史面全不收**（XP 日历/账本摘要如实
保留）；课程改名（只动显示名，宪章目标原句不动）；归档 = enabled 翻转（数据零删零改）；
删除 = 逐字输入显示名强确认 + 三条如实后果。

allo 现状：软删墓碑 deleted_at（069）+ 归档（044 课时归档，非课程级）+ deleteReviews
可选连带删卡 + 简单删除确认；**无课程级 enabled/改名/概况读数/强确认**。且 r3 报告指出
一个连带问题：allo 的删除可选连带删卡——若采纳 learnhub 的「学习记录保留」强确认文案，
必须先裁决连带删卡语义（不得虚诺）。

需要裁决：

1. **「现存且启用」口径**：allo 引入课程级 `enabled` 开关 + active 课程集单源函数，收束
   全部安排面查询？还是维持现状（deleted_at 即唯一口径，无归档暂停态）？**推荐采纳**
   （归档/删除二分的产品价值明确：删除不可逆、归档可逆暂停；allo 已有删除，缺暂停）。
2. **改名**：课程显示名可改（`UPDATE learning_courses` 一条）——目标原句/learning_goal
   不动。**推荐采纳**（成本近零）。
3. **删除语义与强确认**：(a) 维持 deleteReviews 可选 + 强确认升级为「输入显示名 + 后果
   按用户勾选如实动态告知」；(b) 对齐 learnhub：删除永远保留账本、不提供连带删卡（文案
   可如实承诺「学习记录保留」）。**推荐 (b)**（语义更干净；「复习卡要不要删」交给归档
   暂停解决，删除 = 罕见破坏性动作语义单一）。
4. **概况四读数**（节点数/已结算/今日到期/累计 XP）+ 列表行展示——随采纳面顺带。

约束：历史面不过筛（日历/统计聚合如实保留）要与二轮 g1 的「XP 日历不过课程筛」对齐
（同一条裁决的两处落点）；「现存且启用」集是二轮 t1 XP 结算读数的前置。
