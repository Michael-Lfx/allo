## 实现与边界

复用宿主既有 `config/voice_companion.json` 原子写入，在其 `feedback` 字段保存模式、音量和回复播报偏好，不新建配置服务、数据库表或模型凭据。默认轻量、提示音50%、回复播报开启：标准短音约为素材幅度-6dB，提醒和等待音再减半，约-12dB；百分比不是声压承诺。

宿主 `/api/voice/companion/feedback` GET/POST 使用新增DTO；POST为增量字段，省略项保留。既有模型config公开字段/路由保持原样，模型设置和声音设置互不覆盖。并发声音更新串行合并，非法音量在写入前拒绝，旧格式没有feedback时使用明确默认值；非法已有文件不会被默认值覆盖。

响应区分 `requested` 和可空 `effective`：未连接或同步失败时只说明已保存，不能宣称进程已应用。启动通过已有子进程环境装配传入无敏感信息的JSON，运行中经已有回环地址和临时控制凭据更新；凭据不进前端或命令行。私有 `/api/voice/feedback` 及 `/preview` 沿用现有中间件，没有新认证系统或绕过令牌。

daemon将模式统一用于转场音和可选提醒：必要模式保留唤醒、识别、追问、结束/停止、错误，省略提醒与处理轻音；关闭提示音或音量0时不输出提示。关闭回复播报时不调用TTS、不冒充合成/播放，仍保留模型文字并进入四秒文字追问。设置变化作用后续输出；这里不把设置开关当作取消后台任务。

显式试听采用已有单输出端，在Idle检查并可被真实语音输出抢占，不调用wake、ASR或模型；会话繁忙、提示关闭/音量0、设备或输出失败均返回具体错误。设置页提供六类语义试听，使用已保存设置；待服务开启且有实际有效设置时才可试听。试听不会单独打开新的采集源。

设置页复用既有Settings行、Arco控件与语义主题，保留保存失败后的草稿；迟到读取不能覆盖保存后的状态。活动面板/窗口诊断展示最近提示类型、排队/开始/消费完成/失败/取消/跳过及本地化原因。输出端消费完成不等于人耳已听到，重连只读历史状态，不补播。
