## 3. 调用链与证据边界

- 通用补全的 LlmRequest.thinking=None（nomifun-ai-agent/src/factory/provider_config.rs:625–640），没有显式禁止推理。项目已有 one_shot_completion_no_thinking / streaming_completion_no_thinking（532–538、646–670 行），可以复用，不需引入新依赖或另一套 provider。
- thinking=None 不足以证明云端实际开启推理。当前日志没有首响应、首文本 token、推理 token 或各阶段计时，不能把云端排队、网络和推理中的某一个认定为更深层根因。

此前自动回归证明了超时返回、停止和状态恢复；受控模型通过并不能证明真实 Flowy 模型持续在 8 秒内完成。上一轮交接已将真实云模型和 Owner 验收单列，本次实测揭示了这一服务时延缺口。

## 5. 低延迟补充：关闭推理、流式文本与首音（2026-10-19）

### 5.1 8 秒的定义与承诺边界

建议验收指标采用“用户说完 → 开始听到有效回答”的首音时间，另行记录全文/整段播报完成时间；不能把提示音、“收到”或 playback_finished 当成有效答案首音。任意网络、上游排队和服务故障下，无法仅靠客户端逻辑保证云端实质回答一定在 8 秒内到达。可以设定首音 SLO，并在截止时给明确失败反馈，保持下一轮可用；这些都需真实服务样本验证。

8 秒作为首音目标，不应继续直接等同“整段模型生成必须结束”。开始产生有效回答后另设有界总时长及空闲超时，停止仍立即取消整条生成/合成/播放链。不得为了达标而静默无上限延长请求。

### 5.2 当前代码还没有端到端流式首音

1. provider_config.rs:616–640 已有 TextDelta 回调，但 one_shot_completion 最终仍拼接完整输出返回；语音当前调用这一接口。关闭推理应优先复用 streaming_completion_no_thinking / one_shot_completion_no_thinking，并验证协议映射及实际模型是否遵守，不能只凭函数名宣称有效。
2. tts.rs:403–447 虽使用 WebSocket，但先将音频加入 Vec，等待 turn.end，然后整体 decode_audio_to_wav，最后一次发送到音频通道。接口名 synthesize_stream 不代表当前实现已边接收边播放。
3. 本次 4679ms 日志是合成加整段播放完成耗时，没有单独首音时间，不能用它计算 TTS 首音延迟。

### 5.3 建议串行实施顺序

- **第一片：现有链路关闭推理并测量。** 不改模型归属和 runtime；保留短回答要求，按合法完整 JSON 的实际输出需求收紧输出预算，避免因截断产生无效 JSON。记录首文本、完整模型输出、TTS 请求、首音进入 sink、最终 drain。减少 max_tokens 不等于一定缩短首 token，需要实测。
- **第二片：模型流式到分句播报。** 沿现有补全适配接口接增量输出；先得到明确且校验通过的聊天意图，再把完整、可独立表达的短句送入 TTS。UI 同步显示增量并标识生成中。不得把未闭合 JSON、内部推理或尚未校验的任务 ACK 直接读出来；现有整段 JSON 决策协议需要明确的增量契约，不能简单逐 token 转 TTS。
- **第三片：合成与生成重叠。** 首个短句合成并播放时，模型继续生成后文；允许至多一个后续句子的预取，按顺序消费，复用当前 generation 取消和 sink 背压。每段 Edge 请求仍有握手/合成成本，过碎切句会增加请求和 429 风险，不逐字合成。先以完整短句降低等待，再评估真正的音频增量解码，避免一开始重写整套 TTS。
- **同一回答保持一次播放生命周期。** 不能每播一句就调用会结束本轮并开启追问的 play_response；必须等整段回答最终 drain 后才开始 4 秒追问。停止清空队列与预取，流错误保留已展示文字并标明未完成，迟到片段不能进入下一轮。
- **任务权限不提前。** agent_task 的“已接单/正在执行”仍以宿主真实接受回执为准；流式文本不能绕过目标持久化、幂等、工具权限或实际审批。

建议验收：真实模型连续首轮/追问/再唤醒记录首音分布，目标 P95 首音不超过 5 秒、8 秒内进入有效回答或明确失败反馈；前者是新目标，尚无实测达标证据。分别报告成功率、超时率、首句与整段时延，失败样本不得从统计中移除。若首个可用文本本身已超过 8 秒，分句播报不能挽回该轮的 8 秒目标，应继续定位服务延迟或评估另一个已配置的补全适配。

本补充仅为方案核对，未修改业务代码或执行云端采样。
