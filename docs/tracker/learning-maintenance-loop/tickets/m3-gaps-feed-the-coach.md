## Question

「容器/接口/元素未教」这类**概念缺口** findings，修补回合改不了（它只会
结构 op），教练也从来看不到（上下文九块里没有 findings）。于是评审反复
发现同一个底座缺口、反复记进留痕、没人补——本课三条相关 findings
（seq 13/14/15）就是同一件事的三个切面。

## 已核验事实

- 教练上下文九块（`CoachContext::render`）：目标 / 地形清单 / 地形门口 /
  就绪 / 花名册 / 已教账 / 覆盖读数 / 行为摘要 / 登记表切片。**无 findings**。
- findings 表里有完整的缺口描述（issue + advice），且是评审原文——比教练
  自己从花名册推断更直接。
- 直接全量回灌会撑爆上下文：本课已 16 条，且同一缺口会跨轮重复（seq 13/14/15
  是同一件事）。**必须去重 + 封顶**。
- 这是 ADR-0042「情形 B：前置补源」的最小切片——**不做**定向源批调度、不做
  递归深度/预算，只把缺口摆到教练面前，让它自己决定下一批长什么。

## R

- **R-a 抽取**：从 findings 里取「概念缺口」类，去重（按 issue 归一化后的
  文本相似度或 advice 提到的概念名去重），取最近 K 条（建议 5，常量）。
  分类口径取保守：`source = 'concept-review'` 且 `field ∈ {teaches, assumes,
  mints, title, scope, ""}` 且 issue 含「未挂号/无出处/未教/缺」类措辞——
  **拿不准的宁可不进**（误灌噪声会污染教练判断）。
- **R-b 注入**：教练上下文新增一节「【未处置概念缺口（评审留痕）】」，位置放在
  【已教概念账】之后、【覆盖读数】之前（离「该长什么」最近）。每行一条：
  `- {issue 的一句话}（建议：{advice 首句}）`。空 = 整节不渲染（off 臂逐字节
  回基线）。
- **R-c 开关**：`NOMI_LEARNING_COACH_FINDINGS_INPUT`，**缺省 off**——先按 A/B
  定缺省，不预设收益。
- **R-d A/B**：冻结二进制，同课同形两臂各 ≥2 轮自动补批：
  - on 臂：缺口节在场；
  - 读数：①教练产出里**覆盖缺口概念**的节点数（人工判读 or 机械：节点 teaches
    ∪ 铸名里出现缺口概念名）；②单轮墙钟与教练思考 token；③打回率。
  - 判据：若 on 臂覆盖缺口显著更高且打回率不升 → 缺省改 on；否则保持 off。

## Acceptance

- 单测：抽取（去重/封顶/分类边界）、渲染（节位置、空态不渲染、off 臂逐字节
  回基线）、`NOMI_LEARNING_COACH_FINDINGS_INPUT` 开关语义。
- `cargo test -p nomifun-learning` 全量绿 + fmt。
- 真机 A/B 读数进 Resolution（两臂各 ≥2 轮）。
- 结论落字：缺省 on / off / 样本不足。

## 回退条件（负优化判定）

- on 臂打回率上升（缺口节让教练一次想补太多，批被评审打回）→ 保持 off。
- on 臂教练思考 token 显著上升（+30% 以上）而无覆盖改善 → 保持 off。
- 缺口节注入后教练产出跑偏（例如长与缺口无关的节点）→ 回退 R-b。

## 范围外

- ADR-0042 的完整链接器（定向补源批、递归深度 ≤2、单 run 预算、Degraded
  兜底分流）。
- 让 findings 自动推进水位（水位是「修补已读」，与教练消费无关）。
