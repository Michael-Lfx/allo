## 一、已核验事实（2026-11-25 对码 + 库查证）

### 三个回合各自的真实状态

| 回合 | 机制 | 真实运行情况 |
| --- | --- | --- |
| 生长（coach） | 9 块上下文、每批 ≤5 节点 | 正常，sb1 后教练读折叠地形清单 |
| 挂载（mount） | 节点 → 结构块导航事实；待挂集增量；契约门 | **sb2 后可用**：生长落库唤醒仅挂载，真机 8 秒闭环；现存 32 条、0 未挂载 |
| 修补（repair） | 读未消费 findings + 挂载观察 → 七型结构操作 → 全量复核 → 写结构 | **从未运行**：动作簿零行、`learning_maintenance_state` 零行 |

### 修补的能力边界（决定消费者能不能对上）

- **输入**：`findings`（水位之后的全部行，不分来源）+ 挂载观察（结构外/空块/超载块）。
- **输出**：只有 7 种**结构级**操作——`add_edge / remove_edge / flip_edge /
  add_block / split_block / rename_block / merge_blocks`（`structure_ops.rs`）。
- **它不能**：新增节点、改铸名、改别名、补概念出处。那些是内容层的事。

### 16 条积压 findings 的真实内容（本课 seq 1–16）

三类，动作空间完全不同：

| 类型 | 实例（原文节选） | 能修它的动作 |
| --- | --- | --- |
| **概念缺口** | 「已教概念账中未见容器、接口、元素、返回类型…疑似课程在抽象与类型系统线的前置底座存在缺口」 | 长一个节点教它（**教练**） |
| **登记面** | 「提名别名『Option 类型』与定义不完全对应：Option 只表示有/无」 | 改别名 / 分铸（**目前无动作空间**） |
| **判定注记** | 「接口/容器是编程领域常见用语…本批把它们作为描述性用语放行」 | 无需动作（**审计留痕**） |

### 水位语义（容易误解，先钉死）

`applied` 与 `noop` **都推进水位**（`learning_graph.rs:1351-1357` 注释原文：
「applied/noop 才算本回合读到的留痕已消费」）。所以水位的意思是
**「修补已读过」**，不是「已修复」。任何把水位当「已修复」用的消费面都会
把信号吞掉——这是本设计的第一条纪律。

### 定时臂的 bug（W1）

`nomifun-app-server/src/lib.rs`：`last_run` 在每个 30 秒 tick 之后被无条件
重置，而到期判断要求满设定间隔（下限 30 分钟）——**任何运行时长下都不
成立**，定时维护自上线从未运行。sb2 的唤醒臂不依赖它（唤醒分支连
`last_run` 都不碰）。

## 二、顶层设计

### 原则

1. **每个产物都要有消费面**（用户铁律：上下文里有 ≠ 用户能看到）。
2. **信号必须路由到有动作空间的消费者**（ADR-0042 的教训：动作空间优先于执法强度；没有动作空间的信号只会诱使消费者乱动）。
3. **水位 = 已读**，不是已修复；展示与消费解耦。

### 三层职责 + 四个消费面

```
                ┌─ 结构层（map）     修补：7 种结构 op
信号 findings ──┼─ 内容层（nodes）   教练：下一批长节点
                ├─ 位置层（navigation）挂载：node→block
                └─ 人（用户）        展示：看见了什么
```

| 信号类型 | 消费者 | 形态 |
| --- | --- | --- |
| 结构缺陷（结构外节点/空块/超载块/块边界重叠） | **修补** | 七型 op，全量复核后应用 |
| 概念缺口（X 无出处 / 依赖未教概念） | **教练**（下一批） | 上下文新增一节「未处置概念缺口」 |
| 登记面（别名与定义不符） | **无动作空间** | 只展示，不自动改 |
| 判定注记（"按描述性用语放行"） | **人** | 只展示 |

### 三条关键决定

**D1 修补后必须自动重挂。** 修补应用 = 结构 hash 变 = 全部挂载失效。若不
重挂，地形清单静默退回全量（sb1 的教练侧收益归零）。复用 sb2 的唤醒通道：
修补 `applied` 后登记一次仅挂载唤醒。

**D2 修定时臂的 bug，但先真机手跑一次。** bug 是 bug（不是有意设计），修它
才会让维护回合真正跑起来。风险是「从未在生产运行过」——缓解：先手动跑一次
修补，检查产出的 ops，再依赖定时臂。水位天然防重读：读过的 findings 不再
触发下一轮，不会形成空转燃烧。

**D3 findings 展示与水位解耦。** 展示 = 「最近 N 条留痕 + 是否已被修补读过」，
不按水位过滤。否则一次 noop 就能让用户的可见面清空。

### 明确不做（本轮）

- **完整链接器**（ADR-0042 情形 B：定向补源批 + 递归深度 + 预算）——m3 只做
  「缺口回灌教练」这一最小切片，不做源批调度。
- **自动改写登记表别名**——无可靠动作空间，只展示。
- **修补自动应用而不给用户看**——m1 先行，m2 才让修补跑起来。

| id | 票 | 风险 | 依赖 |
