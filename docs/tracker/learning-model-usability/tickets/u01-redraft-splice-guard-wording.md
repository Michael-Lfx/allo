# u01：点修不再让模型搬运未点名节点

## 问题与证据（审计①#1#2，证实）
- 修订纪律要求未点名节点「逐字保留」（`learning_graph/mod.rs` ~:811），却要模型整批重发 JSON；守卫 `redraft_guard_violation`（`growth_retry.rs` ~:158-198）整对象 PartialEq 比对。
- 真机 run-1793951137445：重裁把未点名节点 purpose「粗/中/细」改成「粗、中、细」→ 守卫拦 → 原地重试又改该节点 intent（「手冲」→「冲煮」）→ 二次越权耗一轮；run-1793949722364 四次调用逐字节同败、整跑超时作废。确定性复现。
- 守卫文案「未被打回报告点名的节点「X」被改动」把 X 嵌在句中，模型 note 自述「将所点名的…节点恢复」——读反了。

## 实施要点
- [ ] `growth_body` 重裁解析后、守卫前：对上一稿中**不在点名集**且**候选稿里同标题仍在**的节点，用上一稿该节点**整对象回填**（抹掉标点/措辞漂移）；候选稿里缺失（改名/删除）的未点名节点**不回填**，照旧走守卫（避免把「改名」变成「新旧并存」）。新增节点、点名节点一律以候选稿为准。
- [ ] 守卫文案改为指令式且不把节点名写成可被误读的主语：「以下节点不在本轮打回范围内，必须与上一稿逐字一致——直接从上一稿复制该节点 JSON，任何字段（含标点）都不要改：「X」」。
- [ ] 修订纪律补一句（on 臂）：「未点名节点由系统按上一稿原样回填，你对它们的改动不会生效；只需认真改被点名的部分」。
- [ ] smoke grow 读数行追加 `redraft_spliced={n}`（回填节点数）。
- [ ] 开关 `NOMI_LEARNING_REDRAFT_SPLICE`（缺省 on 待 A/B）；off 臂行为与基线逐字节一致。

## 三件套
- **主指标**：每跑守卫原地重试次数 + 被守卫耗掉的轮次。基线：r01 两跑各「原地重试 1 + 耗轮 1」；目标：同标题漂移类 0。
- **护栏**：点名节点改动照常生效；批次过门/评审结果不劣化；既有 growth_retry/guard 测试全绿；新测：漂移被回填、改名节点仍触发守卫、新增节点保留、off 臂逐字节。
- **推翻条件**：A/B on 臂出现「回填导致评审新增问题」或落库批次含与点名修改矛盾的旧内容 → 默认 off。
