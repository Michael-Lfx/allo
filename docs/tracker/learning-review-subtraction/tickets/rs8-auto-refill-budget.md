## Question

自动补批的墙钟无上界：11-23 实测单轮 18 分钟（返工环 + 云端方差叠加），
理论尾部更长（上游 38 次调用史有 59k 呓语 278s、死因重试 +303s 等形态，
叠加打回环可到 19 分钟+）。上游 learnhub #257 已有现成解法与纪律：
`AUTO_REFILL_GROW_BUDGET_SECS=600` 墙钟预算只注入自动补批路径（手动 grow
不设），判定纯内存、不中断在途 LLM 请求。allo 无任何墙钟上界。

## 已核验事实（2026-11-20/23 对码）

- allo 生长链对自动补批与手动触发完全同路径，无预算缝；上游把两者区分
  （自动=预算内，手动=用户在场不受限）的理由：自动触发的无界尾巴发生在
  用户不在场的后台，可预测性比完成率更重要。
- 上游到点语义（#253/#257 修订后形态，严格加法纪律的范本）：
  - 判定点 = 每次 attempt 前 / 评审前 / 下轮点修前；
  - 已过全部门的批**本尝试照常落位**（Stopped 留痕）；
  - 未过门批 → `GrowthError::Exhausted` 且 last 以「自动补批超时」开头
    （**缺口点名，不静默**）；
  - 预算是节奏限制不是落位闸门——只在能帮时改变结果。
- 11-23 本轮若挂 600s 预算：01:34:58 起跑 → 01:44:52 到点，当时 attempt-1
  评审已过第一次（393s）但结论作废重试中——按上游语义本尝试未过门 →
  Exhausted 点名缺口。与实际（18 分钟后落库）对比：预算版早 13 分钟失败
  可见，代价是这一批不落库。**这正是 A/B 要量的取舍**（纪律性 vs 完成率）。

## R（上游 #257 移植；用户裁决 2026-11-23 灵活纪律）

- **R-a 开关+缺省**：`NOMI_LEARNING_AUTO_REFILL_BUDGET_SECS`，缺省 600；
  设 0 = 关（等效现行为）。只注入 auto_refill 路径的 `run_growth`，手动
  grow / 重访批不设（上游同款区分）。
- **R-b 判定语义逐字平移上游**：判定点三次（attempt 前/评审前/点修前）、
  纯内存、不中断在途；到点 = 已过全门批落位（留痕）+ 未过门批 Exhausted
  点名缺口；后续尝试预判预算（不再白跑）。
- **R-c 读数**：预算触发事件进生成报告与 findings 留痕（补了什么/停在
  哪/剩余缺口点名）——上游 Stopped 行同款。

## Acceptance

- 单测：上游手法同款——预算常数测试钩子（如 30s）强制走超时路径，断言
  已过门批落位 + 未过门批 Exhausted + last 前缀点名；手动路径无预算零
  影响。
- `cargo test -p nomifun-learning` 全量绿 + fmt。
- 真机一次长轮观察：预算触发时任务终态与缺口点名可读。

## 回退条件（负优化判定）

- A/B 语义对照（与本波 rs7 的 A/B 同跑同读数）：若预算档的「批次完成率」
  显著低于无预算档且无补偿收益（单轮时长的改善被落库量下降抵消）→ 缺省
  改 0（关），开关留运维面。
- 预算把"本可落位的 run 变成失败"超出现有语义（提前中断在途评审且该评
  审本可过）= 违反严格加法 → 实现有误返工。

## Resolution

已施工收口（2026-11-24）。**结论：机制落地，缺省按回退条件改关；开关保留
为运维面，缺省值待新数据再定。**

- **落地**（wave/rs8 8753153e4 → merge 36ebf7161；评审修复批 28e974d29）：
  `NOMI_LEARNING_AUTO_REFILL_BUDGET_SECS`（switches.rs 单源）；`GrowthBudget`
  注入 `run_growth`，判定点三次（attempt 循环头 / `concept_review` 前 /
  重裁前），纯内存不中断在途；到点 = 已过全门批落位（note 留痕）/ 未过门批
  `stop_reason = budget_expired` 且失败文案以「自动补批超时（墙钟 N 分钟）：
  」开头点名缺口；留痕进 `learning_structure_findings`（source =
  `growth-budget`）。

**已申报偏离（评审轴核对通过）**：注入臂含 `Settlement`——allo 只有
`kick_growth_with_trigger` 一个 spawn，四触发源共用，枚举自身把
Settlement/AutoRefill 注为「自动补批触发①/②」，只给②设预算会让最高频的
结算钩子臂维持无界尾巴。手动 `grow` 不注入。

- **真机读数（2026-11-24，冻结二进制 250169ebe，基线档 R1，auto_refill 路径，
  缺省仍为 600s）**：

  | 调用 | 耗时 | 结局 |
  | --- | --- | --- |
  | 起草 | 24s | 结构门打回 |
  | 重裁 | 252s | 过结构门 |
  | 评审 | 301s | 打回（1 个问题） |
  | 重裁 | 145s | 预算到点，不再发起评审 |

  墙钟 706s，`state=failed`，失败文案「自动补批超时（墙钟 10 分钟）：本批
  尚未过评审门，不再发起评审（3 个节点在途作废）」——**缺口点名可读、非静
  默失败，机制本身按设计工作**。对照 11-23 同形轮（无预算）：继续第二次评
  审后 1089s 落库。

- **按回退条件判定**：这一轮预算把「慢但能成」截成了「可见失败」，批次完
  成率下降而无补偿收益（单轮只快了约 6 分钟，代价是 0 落库）。allo 单次评
  审思考 ~5 分钟，一次返工即吃满 10 分钟；上游 #257 的 600 建立在批次更小、
  单次评审更快的形态上。**→ 缺省改关**（`AUTO_REFILL_BUDGET_DEFAULT_SECS =
  None`，未设/非法值同为关；设正整数秒启用）。
- **测试面同步**：5 个预算臂测试原依赖「未设 = 600」让预算注入，缺省改关后
  红——已改为各自显式声明窗口（`switch_env_guard(…, Some("600"))`，全部
  `#[serial]`）。测试语义不变，前提显式化。
- **检查**：全量 `cargo test -p nomifun-learning` **1048/0**；fmt 干净。
- **遗留**：缺省值待 ADR-0018（结构退出评审输入，评审输入减约三分之一）
  落地后的新数据再定；`auto_refill` 生产触发外部可达（`POST grow
  ?trigger=auto_refill`）时用户在场也受预算——票面语义如此，记录不修。
