## 3. 必修问题与最小修复

### R12-A1 [Required / P1] A 忙碌时，生产 recorder 仍不能完成 B 的追加

- 位置：[manager:454](../../../../crates/backend/nomifun-app/src/voice_companion_manager.rs#L454)、[service:10983](../../../../crates/backend/nomifun-conversation/src/service.rs#L10983)。
- `preflight` 去掉 busy 判断只改变前置入口；随后 `record_pair` 仍调用 `project_voice_dialogue_pair`，后者在 Conversation busy 时直接返回 Conflict。B 的 `projected` 无法变成 true，`task_configuration` 又要求 projected，所以正常 A 活跃时 B 到不了持久 FIFO。流式显示过部分回复不等于时间线已落盘或任务已排队。
- 新唤醒时若候选会话忙碌，[resolve_target_conversation:243](../../../../crates/backend/nomifun-app/src/voice_companion_manager.rs#L243) 还会改落默认“语音助手”，不是复用该 canonical workspace 的语音 Conversation。
- 最小修复：在冻结绑定阶段确定工作区语音 Conversation；原文用 busy-safe append 落盘，快回复独立追加，不能通过改投默认会话回避 busy。不得删除普通发送的并发保护，也不得把 B 注入 A 的模型输入。
- 出口：生产 recorder/worker 中阻塞 A 的真实 runtime，再说 B/C；B/C 原文、快回复和 queued 都存在于相同 Conversation，A 的 message/runtime turn 和输入不变。

### R12-A2 [Required / P1] 一句原文仍生成两个用户消息，且可能把普通聊天转成语音任务会话

- 位置：[service:11007](../../../../crates/backend/nomifun-conversation/src/service.rs#L11007)、[tasks:681](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L681)、[runtime:126](../../../../crates/backend/nomifun-app/src/voice_task_runtime.rs#L126)。
- recorder 的 pair 投影已创建用户消息 M；任务入口却生成新 message_id N，再 append 同一句 ASR。R1.1 单独的 append→bind 测试绕过 recorder，不能证明生产只有一个用户气泡。当前冻结结构只传 conversation_id/display_text，没有传 M。
- [resolve_target_conversation:238](../../../../crates/backend/nomifun-app/src/voice_companion_manager.rs#L238) 接受任意本机 nomi 候选；[ensure_voice_task_policy:5657](../../../../crates/backend/nomifun-conversation/src/service.rs#L5657) 给它写 voice/voice_task_workspace，改变既有普通聊天的任务策略。两个同工作区普通聊天仍可成为两个不同语音目标，不能据 workspace creation key 宣称 canonical 复用已完成。
- 最小修复：原文稳定 message_id 从 recorder 日志贯穿 ledger/append/bound-send/查询/取消/审批；普通候选只提供工作区来源，目标是该工作区专用语音 Conversation。快回复单独落盘，不重新制造用户消息。旧普通会话不被隐式 stamp 或改变模型/权限。
- 出口：`recorder_user_id == ledger.message_id == first_receipt.message_id == replay.message_id`；只出现一条原文，来源普通聊天的 extra/model/preset 保持不变。

### R12-D [Required / P1] 出队没有核对目标 Conversation 的实际冻结配置

- 位置：[tasks:533](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L533)、[runtime:133](../../../../crates/backend/nomifun-app/src/voice_task_runtime.rs#L133)。
- `prepare_configuration(&next.config)` 只重新解析保存的配置与 preset catalog，并不读取目标 Conversation 当前 model/session_mode/preset。`send_bound` 随后从当前 Conversation 读取 workspace 和当前 epoch 填入 expected 字段。
- 触发：B 排队期间用户编辑该 Conversation 的模型/模式；ledger 里的配置仍有效，校验通过，但发送按已变更 Conversation 运行。直接写 policy 的函数也没有普通 update 的准入/失效边界，不能以“补写 model”代替绑定核验。
- 最小修复：在可信出队边界校验实际目标与冻结配置/来源；不一致明确 blocked/rejected。区别 A 完成导致的正常 turn epoch 推进与工作区/配置代际变更；不能简单锁死旧 epoch，也不能无条件刷新 expected 给旧任务重新授权。
- 出口：分别修改 model/provider、preset revision、session_mode、工作区来源后，B 均不以新配置执行；正常 A→B 仍能推进。

### R12-C [Required / P1] queued + unknown 仍会被自动派发

- 位置：[tasks:343](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L343)、[tasks:508](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L508)。
- 排队项 create/append 返回 Uncertain 时，`persist_mutation_failure` 只改 status=Unknown，保留 queued=true。drain 的选择条件是 queued 且非 Completed/Failed，没有要求 status=Queued；同进程集合仍包含该 command。
- A 终态后会将不确定 B 改成 Delivering 并尝试 send；创建身份尚缺时还会先持久改状态再返回 task_delivery_pending。它违反 unknown 暂停核对的明确门禁。
- 最小修复：可派发状态只允许完整持久的 Queued；创建、append、send 不确定都进入暂停核对分支。恢复依据真实原身份，不能把 status 查询当成授权恢复。
- 已改善但不能扩大结论：active_in_session 阻止重启后的 B 自动 drain；queued reconcile 不再查未发送回执。这两项可保留并继续回归。

### R12-E [Required / P2] 绑定已有目标后，丢失响应仍使用错误的恢复身份

- 位置：[tasks:681](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L681)、[tasks:438](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L438)、[runtime:116](../../../../crates/backend/nomifun-app/src/voice_task_runtime.rs#L116)。
- 已有 target_conversation 被单独保存在 record，但 task.conversation_id 初始仍为空。create_bound 对现有目标只做 ensure_policy，不登记 workspace creation key。若这个调用写入成功但返回丢失，reconcile 却用 workspace key 调 find_created；默认语音入口的 creation key 是 voice:default:user，普通来源也无该 workspace key，原目标因此无法恢复。
- 最小修复：绑定阶段把已知目标身份作为不可变持久事实，核对已有目标而非再按另一个创建 key 查找；确实需要创建的路径统一持久创建 key。丢响应只查询，不能重建/重发。
- 出口：分别注入创建已提交、绑定 policy 已提交、append 已提交后的响应丢失；目标/message 不改变，未核清不启动后继。

### R12-F [Required / P2] 键盘仍绕过持久 FIFO，执行预算也未从真实接受起算

- 位置：[routes:582](../../../../crates/backend/nomifun-conversation/src/routes.rs#L582)、[tasks:550](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L550)、[tasks:683](../../../../crates/backend/nomifun-app/src/voice_tasks.rs#L683)。
- 当前提交未给语音 Conversation 的键盘输入接入 app FIFO。它仍走普通 send；A 忙时可能被拒绝或停留 renderer/localStorage 队列，A 结束后也可抢在语音 B 前执行，破坏同时间线顺序。
- 出队重置 deadline 已实现，但起点在 send 调用前；首次任务也在 create/append 前起算，仍非 R1 §2 约定的真实接受后 30 分钟预算。
- 最小修复：仅对语音 Conversation 共用宿主准入，普通会话保持原状；区分 waiting、delivery 与 accepted execution 时点，保留有界调用和已有取消保护。
- 出口：键盘/语音并发只有一个活动 turn；排队项原 ID 按序执行，键盘默认不自动 TTS；慢准备/发送不侵占真实接受后的运行预算。

### R12-B [Required / P2] queued 不再报错，但新入队没有语音回执及位置呈现

- 位置：[ai-mate:1208](../../../../apps/ai-mate/src/voice.rs#L1208)、[VoiceTaskStatus:32](../../../../ui/src/renderer/pages/voiceSession/VoiceTaskStatus.tsx#L32)。
- 提交返回 Queued 时仅返回 None，然后转 Idle；没有发送 ResponseReady/TTS。另一处“任务已排队”文案只属于用户主动查询 task_control，不能证明入队时离屏反馈已经接通。公开快照也只有单任务 queued 状态，没有队列位置。
- 最小修复：持久入队成功后播一次明确“已排队”，不说已接单；公开最小队列位置/状态，满队列有可理解拒绝。复用现有播放和快照接口，避免新建调度层。
- 出口：真实 worker 的 B 入队，断言 queued 文本/播报一次、零 Error/假 Accepted，runtime_turn_id 为空；双语 UI 核对实际 queued 场景。

### R12-G [Required / P2] collector 的持久去重仍只覆盖近期窗口

- 位置：[collector:145](../../../../crates/backend/nomifun-companion/src/collector.rs#L145)、[collector:520](../../../../crates/backend/nomifun-companion/src/collector.rs#L520)。
- 写成功后再 mark 已修复，并遵守采集开关；这是确实完成的部分。仍只缓存 4096 个 ID，重启只读最近 16384 条混合事件。保留期内较早消息被重播，会再次采集；大量非用户事件也能把 ID 挤出启动范围。
- 最小修复：先明确可重播来源的保留边界，缓存 miss 仍以保留数据的持久身份判重。复用已有事件文件/索引能力，不为此新增通用 outbox/数据库迁移。
- 出口：写失败→恢复→同 ID 一次；超过缓存窗口及混合事件挤出后，重启重播仍只采一次；关闭采集不标记提交。

## 5. 给执行 Agent 的串行收口要求

1. **先修验证身份（H）**：按真实 key 保存/观察，增加完整 B 终态断言。用固定音频/受控模型隔离外部变化，Conversation、ledger、真实 Read 不能替换成空成功。
2. **再统一目标与原文身份（A/E）**：冻结 canonical workspace 的专用语音 Conversation 和预投影 message_id；busy-safe 原文追加、独立快回复；丢响应只核对同一身份。
3. **收口队列状态及冻结（C/D/F）**：未知不出队、重启默认暂停、配置代际核验、键盘共享准入、真实接受后的预算；保持已经通过的容量和取消保护。
