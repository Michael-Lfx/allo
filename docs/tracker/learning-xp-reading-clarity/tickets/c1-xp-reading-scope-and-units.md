## Question

XP 读数行「已结算 0/21 节点 · 剩余 430 est 分钟 · 现步伐约 191 天学完」
无法与实际课程（0/4 课时）对应。口径是什么？怎么让人读得懂？

## 已核验事实（2026-11-17 对码 + 对库验数，用户复核纠偏）

- **用户纠偏**：初诊按「全局聚合歧义」定性是错的——对库验数后定性为
  **f2 漏改消费面的真缺陷**。现存启用课程只有一门（编程课），无多课聚合
  因素。
- **对库实证**（dev 库，与 xp_reading 同 SQL）：该课 **21 节课时**（早前
  19 + 生长批次新增 2），其中 **skipped 17**、completed 0；课程卡 f2
  分母 = 21 − 17 = **4**（截图 0/4 ✓）；面板 total_nodes = **21**（截图
  0/21 ✓，不剔 skipped）；remaining_est = 全 21 课 **490min**（截图时
  19 课 430min ✓ 当时自洽，此后生长 +2 课 +60min）；**剔 skipped 后 =
  100min**——「剩余 430」里 ≈330 分钟是用户已明确跳过的内容。
- **缺陷定性**：f2 的 skipped 分母决议只落了课程卡消费点，XP 面板
  （`xp_reading`，service/xp.rs:248-303：total_nodes :270-278 /
  remaining_est :292-303）没跟上——同一时刻同门课两把尺（0/4 vs
  0/21 · 430min），「对不上」实锤。
- 次要缺陷（仍在）：面板无作用域标注（ReviewBanner:157 挂 XpPanel 不接
  筛选，多课场景仍会误读）；单位词「节点」vs 课程卡「课时」；ETA 步伐
  近零直出 191 天。

## Terms（方案草案，施工前过裁决）

- **R-a（裁决 2026-11-17：C，本票不做）**：作用域标注/跟随下拉均不施工
  ——主缺陷是分母（R-b），单课场景修完即对上；多课误读留观察，复发再
  开小票。
- **R-b（升级为缺陷收尾，2026-11-17 用户复核确认）**：面板分母与剩余
  est **同步剔 skipped**——这不再是联动裁决而是 f2 漏改消费面的修复。
  对数预期（修后）：分母 21−17=**4**、剩余 est ≈**100 分钟**，与课程卡
  立即对上。`xp_reading` 的 total_nodes / remaining_est 两查询加
  `p.status != 'skipped'`（LEFT JOIN progress），ADR-0017 进度尺「现存且
  启用」注释扩为「现存且启用，剔 skipped」（与 f2 决议同源），配
  nomifun-learning 回归测试（skip 17/21 → 面板分母 4）。
- **R-c（裁决 2026-11-17：按推荐 A）单位词**：保留「节点」词，GLOSSARY
  落「节点」词条（节点 = 图课程的学习单位，即课时——词条消歧而非改
  词；图课程域全族在用「节点」）。
- **R-d（裁决 2026-11-17：按推荐）ETA 语境**：「现步伐约 N 天学完」补
  步伐披露（后缀/悬浮「按近 7 天均 X XP」）；步伐近零（7 天 XP 低于阈
  值）降级为「暂无步伐，开始学习后可估算」——巨大天数不再直出。
- **R-e 不做**：后端聚合口径本身不动（全局尺是 ADR-0017 设计）；多课
  分课程 breakdown 不做（读数行非报表）。
