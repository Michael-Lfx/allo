# w01: 越权修改不得经守卫重试洗白落库

## 问题与证据（第二轮审计·教练路 F2 + r01 两跑真机，证实）
- `service/learning_graph.rs:2147`：守卫原地重试时 `previous = Some(candidate)` ——把**失败候选稿**设为新的「上一稿」基准。后果：a) 下一轮守卫比对的是被污染基准，越权改动成了「原样」；b) 模型的反馈里没有原始上一稿可对照。
- `:2271`：门打回后 `point_names = None`（门报告是散文无 node 面），守卫的 `is_named` 退回「报告全文子串」口径——守卫自己的反馈文本提到节点标题，就把该节点变成「已点名」，越权修改二轮免检。
- off 臂真机（run-1793979322412 / ab-grow-off.db）：同一节点守卫两连、耗掉一轮后**越权文本随批落库**，批次 note 自认「曾被误动」。

## 实施要点
- [ ] 守卫原地重试**不再替换 `previous`**：保留原始上一稿为守卫比对与【上一稿】装配基准；失败候选稿整稿作废（模型按守卫文本对原始上一稿重新点修）。核对 feedback 装配对 `previous`/`candidate` 的引用点，保持点修语义（只改被点名处）成立。
- [ ] 原地重试路径显式携带 `point_names`（取自引发本次重裁的评审问题清单；门散文路径无评审问题时维持 None 但守卫比对仍对原始上一稿）——守卫文本自身提及的标题不得构成点名。
- [ ] 新测：①原地重试后守卫仍对原始上一稿比对（失败候选的漂移不成为基准）；②守卫文本提及的标题不构成点名（二轮不再免检）；③既有守卫/重裁测试最小适配。

## 三件套
- **主指标**：越权修改落库数（0 为目标）；真机 off 库已有落库样本为反例。
- **护栏**：点修改正照常生效；守卫两连耗轮语义不变；`ng.redraft.scope` 文案双臂保留。
- **推翻条件**：无（bug 修复类，机械项不挂开关）。
