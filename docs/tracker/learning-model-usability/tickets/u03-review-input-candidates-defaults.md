# u03：让评审的机械表「照抄得出来」、规则「同时满足得了」

## 问题与证据（审计②#3#4，证实）
- 挂号表「常识/缺失行 term 必须逐字取自定义原文」（mod.rs ~:917），机械层却只给点名清单的掩码残片（如「溶风味物质溶解」），模型凭记忆复述定义——两次真机违约都死在这（滤杯循环自证、「可溶物质」）。
- 「宁放勿错/不算问题一律不报」（mod.rs ~:976-981）与碎片「像名词但拿不准按名词处理→必须打回」（~:952）是相反的不确定默认；problems 上限 8 条，run-1793859632428 判 11 个名词时 7 个无法逐条指名（算术不可满足）。

## 实施要点
- [ ] 评审 user 装配（on 臂）：每条提名下渲染「挂号表候选词（取自定义原文，常识/缺失行请从中逐字照抄）：…」——由定义原文机械切出的连续 CJK 片段（复用 definition_audit 切片，不掩码），去重保序。
- [ ] 条款（on 臂）：①「一条 problem 的 issue 可以并列指名多个名词（顿号分隔），名词裁决按词核验，不受 8 条上限约束」；②「『宁放勿错』只管你无法从材料确认的问题；碎片裁决里拿不准的像名词片段仍按名词处理，二者不冲突」。
- [ ] 核验面零改动（validate_fragments 已按子串匹配 problems，多词并列天然可过——加单测钉住）。
- [ ] 开关 `NOMI_LEARNING_REVIEW_CONTEXT_V2`（缺省 on 待 A/B），off 臂提示词逐字节等于基线。

## 三件套
- **主指标**：挂号表违约次数/评审调用；名词裁决未被 problems 指名的条数。基线：真机 8 次评审调用中挂号表违约 2 次；run-1793859632428 名词 11、未指名 7。
- **护栏**：裁决分布不出现大幅偏移（名词数不因条款变化骤降）；评审单次耗时不升 >20%；既有评审测试全绿。
- **推翻条件**：on 臂评审单次输出体积/耗时显著上升（>20%）或名词裁决数骤降一半以上 → 默认 off。
