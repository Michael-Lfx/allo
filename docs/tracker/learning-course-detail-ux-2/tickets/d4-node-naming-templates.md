# d4: 学习节点命名去模板化（生长提示词）

**What to build:** 现网学习节点标题清一色「用X认出Y：Z」类比句式（用团购券认出
看涨期权 / 用保价回收认出看跌期权 / 用留货优先券认出权利金 / 用预售锁价认出期
权行权价 / 用租房押金认出保证金……全是消费场景类比）。正常课程不这么命名。
改 `COACH_SYSTEM`：标题以学科内容本身命名；日常经验类比只活在 purpose 与正文
（它们本就是 intent/scope/purpose 的职责，标题不得承载）；配套句式软提示
（warn 通道，非阻断）。

## 法证证据（2026-11-10 实码核实）

- 提示词：`crates/backend/nomifun-learning/src/learning_graph/mod.rs:494`
  `COACH_SYSTEM`：
  - :499 title 字段说明只写「动作句：解/求/证明/推导/构造/比较/应用/辨析…」
    ——无命名口径约束，类比句式不受限；
  - :500 purpose「练什么 + 从哪段课程外日常经验切入（座位表定位/给物品分类/
    分食物看温度一类生活场景）；找不到日常经验切口的节点不合格」与 :528 节点
    纪律「每个节点的 purpose 必须点出从哪段日常经验引入——但切口只是引入方
    式，节点内容永远是学科概念」——类比被强制且只约束了 purpose，模型把它泄
    进标题；
  - :501-502 intent/scope 字段就是教学意图的正向承载（用户问的「教学意图的相
    关字段」即此）——标题不需要替它干活。
- 软提示通道：`mod.rs:440-481` y01 名字形态点名（`ng.mints.name_hint`，warn 不
  阻断、不进重试反馈），现查「并列字/分隔符」；句式检测可同通道挂靠。
- 评审契约 `growth_contract.rs:47` `REVIEW_FIELDS` 含 title（评审面不动）。
- 真机病历：本仓 2026-11-09 期权课（学习 Tab 截图）五节点全中同一句式；首批与
  手动补批同一来源（COACH_SYSTEM 唯一）。

## 实施要点

- [ ] :499 title 字段说明改写：**以学科内容本身命名**（主题 + 动作/角度，如
      「看涨期权：买方的权利与到期损益」「百分比损益的计算与符号方向」）；
      动作句要求保留；**明确禁止**：日常经验类比不得进标题（类比只写进
      purpose 与正文），不得套「用X认出/理解/看懂Y」「从X看Y」一类固定句式，
      也不得清一色同型。
- [ ] :528 节点纪律补一句：切口（类比）只在 purpose 与正文出现，标题零类比。
- [ ] 句式软提示（票内定挂靠点）：`soft_name_marks` 同层新增标题句式检测——
      标题命中「以『用』开头且含『认出/看懂/理解』」或「以『从』开头且含
      『看』」→ `ng.title.template` warn（非阻断、不进重试反馈，同 y01 口
      径）；测试钉正反例（「用换手率判断热度」属学科动作句不误报？——正例用
      现网病历句，反例自选学科句）。
- [ ] 自检：改后提示词与 :529 声明面条款、:533「标题相应只写一个动作」、
      :535「标题不得完全相同」无冲突；`growth_contract` 的 title 校验
      （TITLE_MAX_CHARS / 批内唯一）不动。

## 验收

- `cargo test -p nomifun-learning` 全绿（新软提示测试 + 既有生长/评审测试零
  回归）；`cargo fmt -p nomifun-learning`；`cargo check --workspace`。
- 提示词 diff 自查：除命名纪律外零语义改动（不碰档位/起点/概念纪律段）。
- **真机复验（必要条件，需一次真实生成）**：新生长批次的节点标题为学科命名、
  无「用X认出Y」句式、无新的清一色同型；已有课程的存量标题不改（重命名不在
  本票）。

## 非目标

- 存量节点标题重写（涉及改库与学习记录，后置另议）；结构侧主干/知识块命名
  （结构生成提示词，现网读数未见同病，留观）；评审契约与档位纪律。
