## 1. 摘要

用户通过唤醒词、Flowy/Bolt 伙伴入口或快捷键，在明确的本机工作区连续交流。简单问题快速回答；复杂问题交给该工作区语音 Conversation 的既有 runtime。原文、短回复、排队状态、执行过程和结果在同一时间线保留，离开屏幕后仍能听到准确的进展和结果。

先完成消息、真实任务和队列闭环，再增加持续倾听、伙伴记忆及本地 TTS。学习 Qoder 的交互和交付机制，不承诺复制其云端实时音频延迟。

## 2. 决策与验收职责

需求提出者负责产品选择和真人设备验收；后续实施者负责代码、定向测试及证据。仓库维护者按现有规则审查公共契约、必要迁移和资源分发。本轮只新增文档，不启动桌面、麦克风、模型或任务执行。

## 3. 背景与证据

现有 KWS → ASR → 文本模型 → Edge TTS 及 Conversation/runtime 任务路径已有实现。主要问题是会话切分、忙碌时落盘、队列缺失、上下文交付和播放通知的可靠性，不能仅靠换模型解决。

## 4. 目标与成功标准

1. 在同一工作区完成“快聊 → 真实任务 A → 续说 B → 排队执行 → 文字和语音结果”，原文只落盘一次，命令至多执行一次。
2. 继承 rev2 的 22 项验收，并通过本文 8 项补充用例；自动验证、网络/设备和 Owner 结果分别记录，不以结构断言代替真实工具操作。
3. 每次测试记录 ASR 完成、首次状态反馈、首个有效回复文本、首音、物理播放完成时间。建议本地排队状态反馈 P95 ≤500 ms；有效回复首句 P95 ≤8 秒是待真机验证的目标，不是任意网络下的保证，提示音不计为有效回答。

延迟样本必须记录模型/provider、设备、网络、输入长度和数量；首次启动与热启动分别报告。超时保留已识别原文和已收到文字，不制造回答或接单成功。

## 7. 产品方案与关键契约

### 7.1 用户流程

启动 → 显示并冻结工作区/语音 Conversation/伙伴 → 倾听并显示原文 → 快速回答或持久入队 → 真实接单、执行及审批 → 保存完整结果 → 声学空闲时播报摘要 → 继续倾听或结束。

任务运行时继续接收发言和键盘输入；同一语音 Conversation 的两种输入使用同一准入。结束连接、停止声音、取消排队项、取消运行项为四个不同操作。关闭连接不自动取消已提交任务；重启后未发送队列默认暂停并提示恢复。

### 7.2 必须交付的功能

| 编号 | 要求与可观察行为 |
| --- | --- |
| F01 工作区归属 | 主窗口、伙伴、托盘和快捷键均由宿主确认工作区；启动后冻结。无法确认时只到默认入口；失效任务不能改投默认工作区。路径规范化复用现有实现。 |
| F02 会话连续性 | 按本机用户与工作区复用语音 Conversation；30 分钟按最后有效用户交互计时，任务/审批期间暂缓轮换。声学连接结束不等于删除 Conversation。 |
| F03 连续连接 | 声学与任务状态独立。就绪后开始 180 秒；讲话、识别和播放有各自有界处理预算；噪声不续期。建议首版单句硬上限 60 秒。非播放期间识别/快模型忙时，后续发言进入有界待处理缓冲，满时明确提示，不能默默丢音或冒充后台已排队。设备断线结束采集，不自动重新开麦。 |
| F04 单一时间线 | ASR 原文尽早保存；快回复与队列状态独立追加，允许任务运行期间写入。不改运行中的 turn，不把模型生成的任务正文冒充用户原话。 |
| F05 上下文交付 | 快模型聊天的投影不会自动进入 runtime 历史。宿主必须从当前语音 Conversation 选取有界上下文与真实任务结果，并记录来源身份/截断信息后冻结到 handoff；跨唤醒仍可引用。不得混入别的工作区。 |
| F06 最小持久队列 | 默认最多 8 个等待项、一个活动语音执行项；容量指等待项。入队成功先持久化再说已排队；只有真实 runtime 接受才说已接单。建议等待上限 30 分钟，执行预算从真实接受起另计 30 分钟；接单准备/发送另有有界期限。 |
| F07 恢复与取消 | 每项保留 command、消息、发送幂等键及真实 runtime turn。发送是否成功不确定先查原回执；unknown 阻止自动重发。replace 等旧任务真实终态；不能确认终态时保持待核对。 |
| F08 配置与权限 | 入队冻结 provider+model、工作区、现有 `ResolvedPresetSnapshot`、session mode 及上下文正文；出队重新校验。未发送配置失效是明确拒绝/阻塞，不是发送结果 unknown。保留 `voice_task_workspace` 和既有语音限制，审批仍由唯一管理器执行。 |
| F09 Flowy 伙伴 | 默认伙伴名 **Flowy**、形象 **bolt**。空库幂等创建，创建/删除共用 roster 修改锁；至少一个。新装默认显示，升级尊重隐藏偏好；不自动启用语音或学习。 |
| F10 记忆边界 | 选择全局生效，连接与每条消息/队列项冻结 owner。用户原文只产生一次采集事件；新语音事件在 collector/learner 按 owner 处理，既有非语音来源不改变。伙伴删除不重分配历史事件。 |
| F11 模型与声音 | 保留独立快模型槽位与任务模型。本 PRD 建议 R1–R4 继续使用现有已配置补全 provider；本地兼容服务可选，R5 再验资源。不引入生产 skeleton、模拟回答或规则伪装的接单。Edge 不可用保留文字；Piper 实现、音色、音素处理依赖及分发条件通过专门门禁后才开放。 |
| F12 结果与反馈 | 完整结果落在会话；摘要保留失败、否定、关键数字和待补信息。无正文不等于任务失败，也不等于目标已验证成功；展示真实回执和“无可播报正文”。用户讲话、响应/播放中延后通知，去重，区分静音、失败、中断和真正播完。结果已保存且声音失败/静音时，通知记为 failed/suppressed 并释放 result_pending、恢复空闲计时，不能无限保持开麦；任务真实结局不因此改变。 |

F09 的显示名称为 Flowy；功能不因用户另选伙伴而要求重新创建桌宠。首版不增加语音退出词、AEC、流式 ASR、Omni/AOQ、新工具系统、Agent Store 协议或 harness 改造。

### 7.3 消息、发送及恢复的技术边界

以下为对 rev2 的推荐收敛，不是已经存在的 API：

1. **身份**：`session_id` 属于声学连接，`command_id` 属于用户请求，`message_id` 属于时间线。`runtime_turn_id` 在实际接受前为空；入队时不得伪造 runtime turn。绑定还包含用户、Conversation、工作区与当前准入 epoch。
2. **存储优先方案**：公开 `MessageRow.content` 的 JSON 保存用户可见原文及非敏感 voice 元数据；完整模型输入复用宿主持久交付记录/回执保存。当前没有独立 message metadata 列。公开历史和事件不得直接透传完整 handoff；恢复从持久正文读取，不能靠 digest 重建。
3. **可信绑定**：Conversation 内增加受宿主调用的“绑定已投影消息并准入”接缝，复用既有 runtime 发送。它校验消息归属、原文、冻结正文摘要、epoch 和对应未执行命令；不能让任意客户端通过指定 message ID 接管别的消息。只扩展 `SendMessageRequest` 的显示字段无法完成这一步。
4. **双视图**：时间线允许展示尚未执行的 B/C；runtime 只接收已出队的输入。不得把排队项加入 A 的执行上下文或调用 steer 代替排队。快聊天及真实结果通过 F05 的冻结上下文显式传递，不假设数据库投影等于 engine session。
5. **兼容**：缺省字段遵循旧路径；旧 receipt 的 payload 比较与继续回答读取保持可用。新 schema 以版本/规范化规则区分，不能给旧 payload 自动补新字段后误判冲突。新命令原文、模型输入或上下文变化必须冲突，不能只比较 command ID。
6. **跨存储恢复**：宿主 ledger 与 Conversation SQLite 不是同一事务；写入顺序、幂等投影标识及重启补齐协议必须通过“每个持久化边界中断”的测试。未形成持久队列收据不对用户说已排队。
7. **迁移门禁**：先用现有 JSON/交付记录证明可行；若无法满足一致性、读取隔离或查询需求，单独提出 append-only migration，未经项目要求的批准不实施。不能用另一份临时数据库回避该门禁。

复用现有 `VoiceModelRef`、`VoiceExecutionConfig`、`ResolvedPresetSnapshot` 与真实回执，不把 rev2 示例中的 `model: Option<String>` 直接作为生产模型契约。

## 8. 交付、实施顺序与验收

### 8.1 分阶段出口

| 阶段 | 纵向范围 | 必须退出条件 |
| --- | --- | --- |
| R1 消息与任务 | 原文/模型输入分离、可信消息绑定、有界上下文、既有 runtime、最小持久 FIFO | 随机文件真实读取；A 运行时 B 原文与回执落盘；A→B 基本串行执行；原文一次、执行一次；普通会话无回归 |
| R2 队列故障闭环 | R1 基础上的取消、replace、期限、重启、丢回执与语音/键盘并发 | 逐持久化边界中断可恢复；unknown 不重复；冻结配置与旧审批不漂移 |
| R3 连续连接 | 双状态、180 秒、单句上限、半双工与设备错误 | 假时钟自动覆盖边界，再由真人验证麦克风/扬声器；关连接不取消任务 |
| R4 默认伙伴与记忆 | Flowy/Bolt、roster 原子保护、owner、采集与学习 | 并发与升级通过；语音来源归属正确；普通伙伴采集、XP、知识挂载和模型传播不回归 |
| R5 本地声音与模型 | 既有补全接缝连接本地服务；通过资源门禁后启用本地 TTS 回退 | 三端资源清单、许可证、校验、CPU/RTF与真实播放证据；缺资源可降级，不能宣称离线就绪 |

R1 必须包含基本持久入队和顺序派发，不能把队列全留给 R2 却要求 R1 验收 B 排队。R5 未选型不阻止 R1 开始，但阻止宣称完整本地声音交付。每片先失败复现，再最小实现、生产入口回归、证据更新；不承诺未经测量的日程。
