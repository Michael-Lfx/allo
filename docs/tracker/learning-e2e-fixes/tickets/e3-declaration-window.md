# e3: 声明窗口时序

**What to build:** learning_graph 建课流在结构+地形完成后**暂停**：前端展示
门口梯队 + 已会声明入口，生长改由用户显式触发（或声明提交后触发首批）——
用户没有「先声明再长」窗口的时序缺陷收口。

## allo 现状（E2E 实锤）

- 建课自动连发：结构完成 → 首批生长自动点火（e2e 实录 07:14 建课 → 07:25
  生长自动开跑），声明入口还没露脸，首批已经把门口 G2 覆盖的「百分数改写成
  小数」教了——声明的价值（免学已会）被时序吞掉。
- 首批生长的触发链待盘：`maybe_kick_growth`（m6 补批触发点）/建课流内显式
  衔接——票内实施第一步先读实码定位触发点。

## 实施要点

- [ ] 定位建课流的生长触发点（建课 handler / maybe_kick_growth / WS
      structure_completed 的衔接实码），改为「结构完成即停」。
- [ ] 前端：结构图 Tab（或建课完成页）在「零节点」状态展示门口梯队 + 声明
      入口 + 「跳过，直接开始生长」次选——声明不是强制的（纯零基础用户直接
      开长）。i18n 双语。
- [ ] 首批生长触发面：声明提交成功（铸概念后）自动发首批 / 或用户点「开始
      学习」——推荐后者（learnhub 语义：生长是学习动作的副作用），票内
      grilling 定。
- [ ] 后续批不受影响（m10 补批/完成节点触发照旧）；`maybe_kick_growth` 的
      建课场景豁免（只豁免首批，补批语义不动）。
- [ ] smoke：structure 档断言「结构完成后零生长任务」；新档或判据覆盖
      「声明→生长」链（e2 落地后声明可真跑）。

## 验收

- 真课旅程：建课 → 结构 → **零生长任务在册** → 声明 → 触发生长 → 首批不含
  已声明门口覆盖的块（声明生效的投影证据）。
- 前端 i18n/theme/dead-css 门全过；typecheck 净。
