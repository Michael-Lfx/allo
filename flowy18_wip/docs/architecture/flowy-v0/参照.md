### 10.1 五款工作台（2026-11-11 横评）

口径：那篇文章是**事实核验、未做同条件性能实测**，只当定位参考。

| 产品 | 仓库 | 定位 | 对我们有用的一条 |
| --- | --- | --- | --- |
| **Cindy** | `makecindy/cindy`（Apache-2.0） | 跨设备任务 ＋「伙伴」 | 固定角色、动态任务：第 5 个样本 |
| **T3 Code** | `pingdotgg/t3code`（MIT） | 多 harness 统一控制面 | 入口不止自家 app（MCP 对外开放） |
| **Orca** | `stablyai/orca`（MIT） | worktree 并行 ＋ Design Mode | **worktree 不是安全沙箱** |
| **Herdr** | `herdrdev/herdr`、`herdr-app`、`herdr-core` | 持久终端 ＋ agent 状态 | **状态必须显式上报**；断线四档 |
| **Alma** | `yetone`（`alma-relay` MIT） | 自己就是 harness，也能当 herdr 的 GUI | 能力层可独立于 UI 存在 |

**三条结论**

1. **五款没有一家用固定 work。** 全部固定角色 / 伙伴 / 绑定关系，动态任务。
2. **状态必须由 agent 显式上报。**
3. **会话与进程的持有者必须唯一。** Herdr 三代不共享会话服务器——反面教训。

### 10.2 AutoLoop：能抄的机制与不抄的范式

**它的范式是 choreography**：人写规则表，事件触发，回执发事件，再命中规则。

**为什么不做主范式**：它的起点是外部事件（运维场景天然如此），用户只配规则；我们的起点是用户意图，**规则没法预先写**，而且用户不会写 JSON。

**但机制可以全抄**，因为它们只依赖「轮次提交契约」，不依赖事件总线：

| 机制 | 用途 |
| --- | --- |
| 四态 `done`/`nothing`/`failed`/`cancelled` | 把「轮次结束」和「任务完成」分开 |
| `fyi` 仅告知卡 | 打扰分级靠类型，不靠计数 |
| `decided` | 记决定，限定作用域 |
| 阻塞协议五条 | 交卡不重试、不重复问 |
| 重试节奏 | 5 分钟起、翻倍、上限 1 小时、第 10 次停 |
| 回执写错只重写回执 | 不重做业务 |
| 领活/交结果的幂等 | 响应丢了不重复干活 |

**一条不抄的**：规则表。我们的「模板」是它的规则的产品化版本——**用户可选、可改，但不是必须写**。

### 10.3 与 sub agent 的区别

| | sub agent | 我们的 work |
| --- | --- | --- |
| 关系 | 一个任务的内部结构 | 多个任务的外部并存 |
| 目标 | 汇总成一个结果 | 各自独立收束 |
| 生命周期 | 随父任务 | 各自独立 |

**sub agent 是「一个任务拆开」，work 是「多件事并排」。** 类比是「多开」，不是「拆解」。

**区分它们的不是 await 链。** await 链断没断只是实现选择 —— 很多 subagent 本来就是 fire-and-forget。

**真正的区别是「系统同时持有几个目标」**：sub agent 和 agent team 的世界里只有一个目标，
只是拆成了子步骤或分配给了几个角色；**work 的世界里有 N 个目标，每个独立收束。**

### 10.4 AutoLoop 借鉴分级：哪些现在做，哪些先记

这一路的借鉴有一个风险：**把别人的事故清单当成自己的需求清单。** 所以逐条分级。

#### A. 首版就要（三类，按成本分）

**A1 · 零成本，写下来就行**

| 机制 | 一句话 |
| --- | --- |
| 「在线」≠「送达」 | agent 心跳不等于用户看到卡（§5.5） |
| 一个成功信号不掩盖另一个 | 产物能打开 ≠ 内容对（§8.10 第二条） |
| 报告聚合 | 同类问题报一条，否则用户关通知（§6.2） |
| 摘要与全文分离 | 卡片写结论，全文进日志（§5.12） |
| 默认值取安全那一档 | 不写配置时是「七类必须先问人」（§5.10） |
| 坏配置整体不生效 | 改错了旧配置继续跑（§5.10） |
| 回答只认第一次 | 后到的直接丢（§8.9） |

**A2 · 要动状态机，绕不开**

| 机制 | 为什么绕不开 |
| --- | --- |
| attempt 四态 ＋ `done` ≠ 完成 | 决定「轮次」和「任务」是两个生命周期（§2.3） |
| work 三类结束 | 「没产物」不能算失败（§2.2） |
| 默认沿用 ＋ 归属后冻结 | 决定 work 的边界怎么划（§2.4、§5.4） |
| 两条通道（对话不排队） | 体验底线，一句话等 PPT 生成完就死了（§5.1） |
| 会话互斥 ＋ 四种不续接 | 不让两个进程开同一会话（§4.1） |
| **打断（停掉正在跑的这一轮）** | 用户说错话要能停；**确认进程已停止才放开**，不是瞬间开关（§5.8） |
| 重试节奏（5 min → 翻倍 → 1 h；第 3 次告知、第 10 次停） | 便宜，且没有它就没有「失败」的定义（§5.6） |

**A3 · 地基，后补代价高**

| 机制 | 为什么后补代价高 |
| --- | --- |
| `token` 只报本轮 ＋ 至少一次语义 | 回执可信度的全部依据（§4） |
| 凭据边界四条 | 不下发上下文／日志不存 token／换 token／配置不在 API（§4.4） |
| 确定性五条 | 无变化不写／单事务／纯函数＋唯一写入者／不复制整表／格式指纹（§5.13） |
| 核验器配置不来自被核验对象 | 我们正好是「能力包配置 ＋ 产物」的结构，天然撞上（§6.1） |

#### B. 先记：首版不做，写清触发条件

| 机制 | 什么时候才需要 |
| --- | --- |
| **规则级暂停（一整类活不再派）** | **不适用** —— 我们没有「规则」这个概念；「这类活先不做」由 work 的「搁置」状态覆盖 |
| 三层并发上限（规则级、Agent 级） | 并发 > 1 |
| `started` 判据（能否安全续接） | 进程外执行——进程内调用不存在「不知道收没收到」 |
| 超时区分「没开始」与「在跑但慢」 | 依赖外部异步系统 |
| 外部事件的三条形状（分级校验／字段上限／幂等键） | 接外部事件源 |
| 回答者白名单、送达凭证一致 | 多通道或多用户 |
| 送达语义细节（幂等键不带版本／未送达已解决） | 有非应用内通道 |
| 告警抑制四步（首报／持续静／恢复报／手动关后再报） | 有持续告警 |
| **ACP 四条已知限制** | 真的走 ACP |
| 按「是否进命令行」分级 | 有外部命令拼接 |

#### C. 不适用

| 机制 | 为什么 |
| --- | --- |
| 回执写错只重写回执（最多两次） | 我们的回执是结构化调用结果，不是「Agent 的最后一条消息」 |
| 链接型卡片及其 7 天有效期 | 不做链接审批，只走应用内 |
| `group` / `tier` / 事件类型通配符 | 没有对应概念 |

**一句话**：**A 三组现在就落进 V0–V5；B 组只写触发条件，不写实现；C 组明确划掉。**

老爷爷的批评是对的——不分级的话，开工的人不知道该删哪条。

### 10.5 OpenAI Dot（Dots）常驻助理四轮实测对照与借鉴分级（2026-11-25）

> **来源与证据口径**：2026-11-25 对 OpenAI 常驻助理 Dot（Dots）完成四轮采样——① 首轮 5 组运营机制追问（工具与主从边界 / 写冲突与复验 / 三层记忆与上下文≠权限 / 中途插话与局部取消 / 审批隔离、打扰节奏与云本分工）；② **青禾项目真机黑盒实测**（报价表 30 万 + 三页 PPT 11/27 + 插话归档 35 万待确认会议记录 + 插话只改 PPT 日期到 11/30 + 审批中追问进度 + 事后审计）；③ B 组 4 项深水机制追问（定时巡检 / 本机非文件共享资源 / 退避止损与子 Agent 冲突仲裁 / 长任务静默心跳与回退清单）；④ **实验 1 反向歧义黑盒实测**（双 PPT + 报价表同场下不点引用卡片裸发「把刚才那份的报价改成 32 万元」，验证结构化消歧卡；其余对抗实验因 Dot 额度耗尽收官）。
>
> **铁律（经 `carl-idea-king` 对抗审查校准）**：严格区分**「截图实证过的行为」**与**「Dot 口头自述的预期规则」**（Dot 自己也明确声明巡检规则是其自设约束而非平台保证）。绝不把云端产品的口头承诺或未来能力的事故清单直接塞进 Flowy 当前排期。

#### 一、已验证黑盒事实 vs 待证伪自述契约

| 维度 | 证据等级 | 核心发现与对 Flowy（`origin/main@526b2336f`）的直接启示 |
| --- | --- | --- |
| **1. 稳定对象标识 ≠ 独立 Work** | **已实证（青禾黑盒）** | 会议记录单独归档成可回查的私人页面链接，未另开重型后台任务；35 万「待确认提议」与 30 万「已确认报价」严格隔离；修改 PPT 日期只影响 PPT 不污染报价表。**结论**：明天还要找回 → 需要稳定 `object_id`；只有存在持续执行/暂停/结案责任时，才建独立 `Work`。 |
| **2. 授权 ≠ 执行 ≠ 验收三时刻分离** | **已实证（青禾黑盒）** | 审批卡（`create blank presentation` / `create page`）挂起期间，对话通道不锁死，追问「执行怎么样了」秒回真相（「需求已锁定、审批卡已弹出、最终文件尚未打开验完」）；交付回执既重开读内容又**逐页看了渲染图**，同时诚实注明「未在 PowerPoint 实测」。 |
| **3. 无引用歧义不乱猜：结构化消歧抉择卡** | **已实证（实验 1 黑盒通过）** | 双 PPT + 报价表在场且不点引用裸发「把刚才那份的报价改成 32 万元」时，Dot **立即停手并弹出 A/B/C 单击选择卡**，具备四项高价值细节：① **卡头明示影响边界**（「我只改你选的那份，其他文件保持 30 万元」）；② **每项附鉴别锚点**（「内部讨论稿（首页 12 月 2 日）」vs「原版报价汇报 PPT（首页 11 月 30 日）」，0.5 秒分辨无需开文件）；③ **按对象类型过滤**（自动排除不可改报价的会议记录 `Record`）；④ **交互降噪**（用按钮卡替代长段文字反问）。Flowy 可在此基础上额外支持多选（如同时改正式 PPT + 报价表）。 |
| **4. 主从边界与并写单写者** | **自述（待证伪）** | 子 Agent 与主控共享大部分工具，但有三条硬禁令：**禁建定时任务 / 禁借分派提权 / 禁直接向用户承诺或交付**；同可写目录默认单写者，独立修改须**独立分支 + 独立工作目录**；「子 Agent 总结是索引不是验收证据，各自跑绿 ≠ 合起来也绿」。 |
| **5. 中途热插话与两态停止** | **部分实证（生成前改需求已验；运行中取消待验）** | 改格式/补检查热注入复用已完成工作；改目标/权限立即停受影响分支；显式区分**「已请求停止」与「已确认停止」**，喊停后交出 5 要素可回退交接清单，界面上把「停主轮 / 停后台子任务 / 关定时计划」彻底分家。 |
| **6. 失败止损、冲突仲裁与诚实心跳** | **自述（待证伪）** | 步内重试仅限只读/幂等瞬时故障（默认最多 1 次）；写操作超时先查是否已生效；**同错零新证据绝不原样再跑**；子 Agent 证据冲突**不投票、不折中**，靠原始真相一次判别检查定胜负；长任务静默期用「上次完成+时间 → 当前动作 → 下次检查/超时点」三段式心跳，拒绝虚假进度条。 |
| **7. 定时巡检与本机共享资源排队** | **自述（待证伪）** | 离线错过 N 次合并补查 1 次并诚实标 `未覆盖` 时段；告警指纹 `(project/env, object, error_type)` 不含时间戳；**静默 ≠ 不耗额度**，连败 3 轮自动暂停；本机桌面焦点/已登录浏览器/8080 端口/Excel 锁文件按**资源级**而非整任务排队，双资源原子防死锁，绝不杀未知 PID 腾端口。 |
