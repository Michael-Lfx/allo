## Question

learnhub #88 立了全系统量纲宣言（用户定调，两轮修正后终稿）：**1 XP = 1 est 分钟 = 1 分钟
专注学习**；量纲一元、来源多元（est 按 1 est 分钟 = 1 XP 计价仅为「完成学习点」一种来源，
复习/quiz/奖励各有定价，按同一量纲入同一账本）；XP 记努力账不记掌握（进度 = 结算数、
掌握 = 证据回放聚合，两把尺严格分离）；est 是尺寸锚（出生即铸、内容层继承）；est 感知面
定位不变（不进门禁、不进调度、不得变成日程）。

allo 现状（对照见 assets/r2 §5）：**三套量纲互相独立无桥**——教练 minutes（1-60 门、提示词
常规 5-30/极困难 60、缺省 10 落 estimated_minutes）；打卡按复习事件计数（缺省 15，与分钟
零换算）；XP 在 companion crate（Lv=sqrt(xp/100)，伴随对话每轮 +2），学习模块零 XP。

需要裁决：

- **(a) 全域采纳**：学习模块宣言 + 桥到结算（完成节点/打卡 → 按 est 计价入 XP 账本，
  companion XP 语义统一或新立学习结算账）。
- **(b) 学习模块内采纳**（轻）：术语与语义统一（minutes 即 est 专注工作量、内容层继承、
  不进门禁不进调度），CONTEXT.md 立词条，教练/内容提示词措辞对齐；**不碰 companion XP、
  不新建账本**——XP 桥属跨模块产品决策另议。
- **(c) 不采纳**：维持现状（minutes 只是字段名，无宣言），本轮跳过量纲题。

连带面：若 (a)/(b)，`minutes` 字段是否更名 est/est_minutes（DB 列 070 风格 append-only，
更名成本）；打卡口径是否挂量纲（现为事件计数）；(a) 还需定结算点与防刷规则（完成即结算？
重复完成？跳过的计价——learnhub 跳过是否计 XP 需回查）。

约束：est 感知面边界照抄（不进门禁、不进调度、不得变成日程——一轮「深度水位门退役」已与
此精神一致）；若 (b)，明示「allo 无 XP 账本，宣言是前瞻预留」。

## Resolution

**速览**：五轮追问六项全定——**完整采纳**（宣言 + 账本）；**统一账**（学习入 companion）；
**三线一次到位**；**全式含惩罚**；**打卡并入 XP**；**代码/契约统一 est**。用户取向：全量
吸收（后四项均取最彻底选项）。

1. **采纳范围：完整采纳**——立「1 XP = 1 est 分钟 = 1 分钟专注」宣言（CONTEXT.md 词条
   = 量纲单源）+ 建学习结算账本。
2. **账本归属：统一账**——学习结算事件（追加只增、回放派生）与 companion XP 并入同一
   账户（learnhub 原话「XP 账本是全任务线账本」）；**companion Lv 升级为总努力级**。
   已知量的跃变：est 20 分节点 = +20 XP，远超对话 +2/轮——Lv 曲线由学习主导（学习产品
   语义上合理）。实现需 learning→账本的写入接缝（实施票定接缝形态）。
3. **结算范围：三线一次到位**：
   - **教新线**：学习图节点 + 传统课时完成按 est 计价（计价 1 est 分钟 = 1 XP）；
   - **复习线**：复习队列推进按工作量当量（题型当量 × 完成题数、下限 3——allo 题型→
     分钟映射实施时定）；
   - **题目线**：自建题/quiz 型会话按准确率分级（0.9/0.6/0.3 档，**恒非负**——测量非
     门禁、无惩罚通道）；与教新线比例分量对同一批作答的去重口径实施时定（不重复结算）。
4. **计价分级：全式含惩罚**——基数额 = 走完全部步骤 + 练习作答完成；全对奖励
   +xp_bonus（缺省 2）；部分正确按正确率比例向下取整（allo 节点完成已有作答 ≥0.6 比例
   信号）；未完成/中途放弃不结算（learnhub 砍短 0 的同义形态）；**检测乱猜 = 负分
   （基数 ÷ 2）**——需补乱猜检测（作答时长阈值；allo 有卡面展示门控先例；learnhub 自标
   此机制风险留档观察、报警阈值可调，实施时同注）；重复完成不重复结算（一次性事实，
   重学员走复习线计价）。
5. **打卡并入 XP（口径统一，非奖励源）**——用户澄清（2026-10-13）：**打卡本身不额外奖励
   XP，动作只是统一口径**——退役的是「复习事件计数」这个日目标口径（`dailyCheckinGoal`
   缺省 15 退场），日的达标读数统一按 XP（缺省 40 ≈ MA 课堂基线）；**XP 全部来自三线
   计价（教新/复习/题目），不设打卡奖励事件**；打卡的 UI 位置由 XP 读数（今日 XP/目标
   达成/ETA）接管；存量打卡数据处理随 071+ 迁移（实施定）。
6. **命名：代码/契约统一 est**——DTO 字段、ng.* 契约键（minutes→est）、COACH_SYSTEM/
   评审提示词措辞、内部命名全对齐 est（语义 = 专注工作量尺寸锚）；**DB 列
   estimated_minutes 原地不动**（列名无用户面，语义注释补上）；契约文档与测试夹具同步。

**边界照抄**（随宣言固化）：est 感知面定位不变（不进门禁、不进调度、不得变成日程）；
XP 记努力不记掌握（与 mastery 两把尺严格分离——allo 已有 mastery 面，正好呼应）；读侧
读数纯投影、零新状态（XP 汇总全部回放派生）；「进度 = 结算数、XP = 努力账」两把尺分离。

**派生影响**（供实施切票）：companion crate 改动（账本接缝 + Lv 口径）、学习完成事件
（图节点/传统课时）、复习结算、自建题结算、日读数与 ETA、打卡退役 UI/i18n（**不设打卡
奖励事件**）、乱猜检测、命名统一（含 ng.* 契约、schema、smoke）。071+ 迁移随本组实施。
