## Question

对照 learnhub 铸名门新进展（#79 名字面兜底 v2.6、#85 别名投影命名面闭环 v2.5），allo 现有
铸名门（assets/r2 §2）**已覆盖精确名撞**（canonical∪别名大小写折叠）+ 批内唯一 + 落库
幂等复用——#79 的名字面兜底 allo 已有同效。真正的增量面：

1. **别名入池闭环三件套**（learnhub v2.5，契约条款：各复用通道把名池新名落为被复用概念的
   活跃别名 colloquial/attestation；名已在池则跳过；名字全库唯一不变）：
   - ① **复用即别名**：allo 走名称解析复用既有概念时（引用解析到别名 / 铸名门改挂），把
     提出的名字落进 `aliases`（allo `models.rs` 已有 `aliases: Vec<String>` 字段）；
   - ② **别名池可见**：教练上下文登记表切片附「概念别名池」行（正名=别名1/别名2）；
   - ③ **选名裁量条款**：COACH_SYSTEM 加「引用已教概念时选最贴合本点角度的名字；新角度
     值得命名可用该名字提名同一概念，铸名门会复用并保留为别名」。
   三件套缺一不可（只做 ① 池不可见模型用不上；只做 ③ 无别名承载）。
2. **deprecated 口径一致**（allo 既有小 bug）：门侧读登记表过滤 `deprecated=0`，但
   `apply_batch` 复用查询与解析查询未过滤——对已退役概念铸名会静默挂到退役行。修法：
   落库查询同口径过滤（或明确语义反转：允许挂回并复活？）。
3. **定义近邻判定**（learnhub `defnear.rs` 字符 trigram 近邻 + `nearname.rs`，既有机制非本轮
   窗口）：allo 现状只有精确名撞——两个名字不同但定义近义的概念会各自铸行，跨课程同概念
   分裂。是否引入：
   - (a) 引入轻量代理（定义归一化 + trigram 近邻，命中即送概念评审复核或直接改挂）；
   - (b) 不引（allo 无真机重复铸名实证；铸名语义面已由概念评审判据③「同概念两个名字打回」
     覆盖——但评审看不到全库定义，覆盖面有限）；
   - (c) 记录待实证（本轮不动，等真机出现重复铸名再上）。

需要裁决：三面各自的取舍。推荐：①全采（闭环价值最高、成本低——复用路径已存在，只加登记
动作与一行上下文 + 一条提示词）；②采纳（小修，口径一致）；③选 (c) 记录待实证（alo 没
有 learnhub 的六批长样本证据量，先拿真机数据说话；若用户要一步到位则 (a)）。
