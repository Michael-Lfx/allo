## 1. 核心原则：TD + 纵向优先

- **TD（测试先行）**：每个波次动工时，第一件事是把本波 VT 套件写成**失败测试**合入分支（挂 feature flag），实现任务卡的全部工作就是把这些测试转绿。
- **纵向优先**：VT 套件从“语料输入”切到“可观测输出”（扬声器帧流 / FSM 状态序列 / SSE 事件流 / 浏览器像素与文案），一刀穿透全部层；层内细节由常规单测守护，VT 不替代单测。
- **Gate 评审 = 跑 VT**：每波出口门禁评审时，评审人只需执行对应 VT 套件与 bsk 剧本，不需要临时设计测试。

## 2. 纵向 vs 横向分工

| 层 | 守护手段 | 示例 |
| :--- | :--- | :--- |
| 层内逻辑 | 常规单测（`cargo test -p`、`ui/` 组件测试） | 重采样精度、SHA256 比对、FSM 迁移表合法性 |
| **跨层竖切** | **VT 套件（本规范）** | 回放唤醒语料 → 200ms 内 wake.wav 帧流出 |
| 浏览器层 | bsk 剧本（§5） | 360px 配对页输码 → 锁定倒计时出现 |
| 黑盒验收 | 基线 TC-AM / Gate（人工 + 真机成分保留） | 72h 挂机、明暗主题人工核查 |

## 5. bsk 浏览器验证规程

bsk = 用户指定的浏览器自动化通道，本规范将其视为**可脚本化的浏览器操作 + 断言能力**（导航、输入、截图、computed style / a11y 树读取、网络条件与 `prefers-reduced-motion` 模拟）。

- **剧本入库**：bsk 剧本随代码入库，命名 `bsk-<波次>-<场景>.md`（步骤 + 断言 + 通过标准），执行记录（截图/日志）归档到波次评审材料。
- **桌面端入口**：`bun run dev:web`（auth 关闭、localhost），bsk 直接驱动 SPA 设置页。
- **配对页入口**：`apps/ai-mate` dev 模式本地起 `:8080`，bsk 以 360px 视口驱动。
- **确定性要求**：进度类断言先以后端测试源触发真实 SSE，再断言浏览器呈现；禁止用浏览器端 hack 注入假状态。
- **人工保留项**：reduced-motion 主观语义完整性、明暗双主题观感，按基线 Gate 2 保留人工签核；bsk 负责截取素材与机械断言（无位移、无过渡时长）。

## 7. CI 门禁接入

- 每个 VT 套件对应一个可单命令执行的入口（`cargo test -p <crate> --test vt_<n>` 形态），接入分支保护；bsk 剧本在具备浏览器环境的 runner 上执行，缺失环境时波次评审人工执行并归档记录。
- 2 小时误唤醒语料在 CI 上以**加速回放**（非实时消费）执行；72h 压测属 Gate 4 真机/长时人工项，不进 CI，以采样压测（10 分钟 SPSC 稳定性、内存曲线）作 CI 镜像。
