# ADR-0017: 删除保留口径——前瞻面过滤、回望面保留

Status: Accepted

Date: 2026-11-13

## Context

课程删除采用墓碑语义（三轮 g3：课程行留 `deleted_at` 位，课时/模块/概念网边/
活动物理删除；复习卡、进度、XP、检测回合、作答与评分流水等学习者状态按
「账本永远保留」留存）。墓碑课留下的悬挂账面（死卡——activity 行已删、永不
复服务的复习卡；悬挂 XP/回合/流水）在 2026-11-13 的全库审计中暴露出一个口径
分裂：`due_reviews` 队列正确过滤了死卡，但记忆面板把 14 张死卡计入「到期」、
打卡面同样虚高——用户看到「14 张到期」点进队列却是空的。而另一面：记忆校准
曲线、XP 总账保留墓碑课贡献则完全正确。

根因是两类读数从未被显式区分过，每处查询各自决定要不要过滤墓碑。

## Decision

以「读数回答什么问题」划一刀：

1. **前瞻可行动面（回答「现在该做什么」）必须过滤墓碑贡献**：负荷预报、
   到期计数、卡片状态分布、日历到期分桶——墓碑课的卡永不复服务，计入即
   是对行动的误导。共享过滤片段（现存且启用：`deleted_at IS NULL AND
   enabled = 1`）为单源实现（ADR-0015 同期口径的三轮 g3 语义，代码化于
   t1）。
2. **回望历史面（回答「发生过什么」）必须保留墓碑贡献**：记忆校准诚实
   统计、XP 总账、复习日志、打卡已锁日——历史发生过就留，删课不撤回历史
   （「账本永远保留」的语义半边）。
3. **墓碑统一形态**：删除时 `enabled` 随 `deleted_at` 一并清零——双状态位
   冗余收敛，半抄过滤（只看 `enabled`）的查询面从此安全；无恢复路径，
   零行为风险。
4. **收尾动作入删除事务**：active 检测回合废弃、死卡打 `archived_at`
   （列现成、全读面已过滤，纯数据自描述），存量由迁移一次性背填。

## Consequences

- 新增任何一个读数面时必须先回答「前瞻还是回望」——前瞻接共享过滤片段，
  回望明确注释不过滤的理由；错边即是 bug（2026-11-13 实证：日历分桶漏
  过滤）。
- 死卡带 `archived_at` 标记后，与归档卡、在学卡在行上可区分；「死卡」
  （悬空卡）成为可查询的状态而非推断。
- 回望面里的墓碑贡献永远在（用户删课后记忆曲线仍含其历史）——这是选择
  而非疏漏；产品若要「删除即从统计隐退」需推翻本 ADR。
