# u07：让「知道档」真的浅讲、让数学错误发布前被看见

## 问题与证据（审计③#3#4#6，证实/推断）
- 条款冲突：用户回合「历史波动率（知道）」+ 意图画像「轻量认课」，但 R14「凡可算量必实算」+ 例题密度 3–6 + 完备面条款胜出——fresh.db 正文 s2 全公式推导+符号表、s3 四道逐步实算例题；预算「中 250 字」被 s1（1330 字）突破，审计只有下限无上限。
- math_verify_failed 在 finish 门 refresh 之后才追加（`service/lesson_draft.rs` ~:144-160）：负样本跑最后一次核验 Fail 后直接发布，模型会话内不可见（核验文案本身信息充分——败因是机制）。
- 修复轮 user 只有审计报告（`learning_loop.rs` ~:493-513），概念面/档位/教学范围不可达（推断）。

## 实施要点
- [ ] （开关 on 臂）系统提示词补「档位优先序」：知道档=认识性讲解，不引入需逐步实算的推导，数值例至多 1 个（如有须经 verify_math）；例题密度/完备面要求只适用于会用、能教档。
- [ ] （开关 on 臂）审计加节长上限 warning：单节正文超过预算行对应字数 2 倍时报 `section_over_budget`（warning，不阻断）。
- [ ] （机械）finish 门判定前汇总本会话 math_verify 的 failed/unresolved；存在则把失败条目（含实算值与修正指引）回给模型**一次**修正机会，再判发布（仅一次，防死循环）。
- [ ] （机械）修复轮开场注入课时上下文（lesson_user_text 同源），审计报告随后。
- [ ] 开关 `NOMI_LEARNING_TIER_PRIORITY` 只管前两项；后两项为正确性/上下文补全，不挂开关。

## 三件套
- **主指标**：知道档节长/预算比、数值例数；发布时 math failed 数。基线：s1 1330 字 vs 中 250；例题 4；负样本跑发布时 failed=1。
- **护栏**：content 臂判据全过；会用/能教档内容深度不受影响（条款限定档位）；数学失败回给模型仅一次，调用增量 ≤1。
- **推翻条件**：on 臂知道档内容出现「只剩定义、无情境引入」类空心化（概念面登场纪律被破坏）→ 档位条款默认 off。
