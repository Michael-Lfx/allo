## Question

XP 读数行「已结算 0/21 节点 · 剩余 430 est 分钟 · 现步伐约 191 天学完」
无法与实际课程（0/4 课时）对应。口径是什么？怎么让人读得懂？

## 已核验事实（2026-11-17 对码 + 对数）

- **口径 = 全部现存且启用课程的聚合**（非单课）：`xp_reading`
  （service/xp.rs:248-303）——total_nodes 数课时行（:270-278）、
  settled_nodes 数 node-completed 事件去重（:279-291）、remaining_est
  未结算课时 est 和（:292-303）、ETA 近 7 学习日步伐（:305+）。
- 对数：0/21 = 编程课 4 + 新建课 ≈17；430 = 两课剩余 est 和；191 天 =
  步伐近零的推算（数学诚实，读感爆炸）。
- 呈现缺陷：①面板不受「全部课程」下拉控制、无作用域标注（ReviewBanner
  :157 挂 XpPanel，不接筛选）；②「节点」vs「课时」单位词混用（分母实为
  课时行数）；③与 f2 剔 skipped 新口径并排不同尺（课程卡 0/4 分母剔
  skipped，面板 21 含 skipped）。

## Terms（方案草案，施工前过裁决）

- **R-a（荐）作用域标注最小修**：读数行加作用域前缀——「全部课程 ·
  已结算 x/y 节点」（或「跨 2 门课」），i18n 双语；后端零改动。备选：
  面板跟随课程下拉（下拉选单课 → 面板切该课读数）——需 reading 接口加
  course 参数 + XpPanel 接筛选 prop，成本高一档；荐先标注、跟随下拉留
  观察。
- **R-b（联动裁决）分母口径对齐 f2**：面板分母/剩余 est 是否同步剔
  skipped（与课程卡同尺）——荐同步（两尺同屏必须同口径，否则 c1 修完
  还是「对不上」）；ADR-0017 进度尺「现存且启用」注释扩为「现存且启用，
  剔 skipped」（与 f2 决议同源）。
- **R-c 单位词**：「已结算 x/y 节点」改「课时」或保留「节点」但在
  GLOSSARY 落「节点 = 图课时」词条——荐后者（图课程域「节点」是既有用
  词，learningGraphSkip 等全族在用；改词成本高且割裂）；关键是 R-a 的
  作用域标注消除主要歧义后，节点词本身可容忍。
- **R-d ETA 语境**：「现步伐约 N 天学完」补步伐披露（如悬浮/后缀「按近
  7 天均 X XP」）；步伐近零（如 7 天 XP < 阈值）时降级为「暂无步伐，
  开始学习后可估算」——巨大天数不再直出。
- **R-e 不做**：后端聚合口径本身不动（全局尺是 ADR-0017 设计）；多课
  分课程 breakdown 不做（读数行非报表）。

## Acceptance
