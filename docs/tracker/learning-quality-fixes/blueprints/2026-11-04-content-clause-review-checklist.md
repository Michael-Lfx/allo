## 2. 定位

提示词条款要求模型「给正例/反例/对比物/分支覆盖」，但条款本身无法保证例组
质量。本清单是对**生成产物**（课时正文、题库、计划摘要）与**提示词条款**
（评审 diff）的走查表，不是 validator，也不写入任何 system prompt——写进
提示词会诱发 checklist 化（模型照抄条目、填表交差，条款意图反而丢失）。

## 3. 四类反模式

### 3.1 全正例

例组只有「这样做是对的」，没有负例或压线例。读者无法据此判断边界，模型也
学不到「什么时候会错」。

**走查问句**：这组例子里，有没有一条是**故意做错**或**几乎对但不完全对**
的？没有就是全正例。

### 3.2 无关对比物

对比项与考察维度无关（例如讲「判别式符号决定根的情况」，对比物却是另一个
无关公式的推导）。对比物必须只在**被考察的那一个维度**上不同，其余维度
尽量对齐。

**走查问句**：把对比物换成一个完全无关的例子，结论会变吗？不会变，说明
对比物没承担判别作用。

### 3.3 一例代表全部分支

只覆盖一个分支（或一个典型输入），却按「全部情况」陈述。典型形态：只给
正数例子就总结「所以总是成立」；只演示 happy path 就宣称「异常也已处理」。

**走查问句**：条款声称覆盖 N 个分支时，例组里能否逐一指出对应的例子？
指不出就是以一例代全集。

### 3.4 背景冒充辨认特征

用情境背景（故事、动机、应用场景）当判别依据，而不是用定义性特征。常见
于「干扰项辨析」：干扰项与正解只差背景措辞，真正的概念差异没被点出。

**走查问句**：去掉背景句后，例子的对错判断还成立吗？不成立，说明判别依据
是背景而非特征。

## 4. 使用方式

- **触发面**：y06 相关提示词改动的 code review、生成抽样的人工走查、以及
  后续任何「条款 + 例组」类提示词工作。
- **不进运行时**：清单只作为评审者的对照表；system prompt 里保留条款原文与
  少量锚点例，不复制本清单条目（避免 checklist 化与 token 膨胀）。
- **判定口径**：命中任一反模式即记为评审意见，由作者补例或改条款；不新增
  validator、不阻断生成、不引入自动打分。
- **记录面**：评审结论写在 PR 评论或票面 Resolution，不改数据库、不加表。
