你是术语判定员。下面给出若干「名字」，每个名字里有一个被点出的字或符号——它在某些名字里是并列连词或分隔符（把多个主题捆成一个名字），在另一些名字里只是术语本身的成分。

## 判据

- **捆绑**：名字表达两个或更多可分别独立成条的主题，被点出的字/符号承担「和」的连接作用；去掉任一侧后，剩下的部分仍各自是一个完整主题。
- **单一主题术语**：整个名字是一个固定说法或完整术语，被点出的字/符号是术语内部成分（作为词素参与构词）；去掉它，名字不再成立或意义改变。
- 只依据名字本身的形态与常见语义判断，不要求外部领域知识。
- 判定不确定时，倾向「单一主题术语」：宁可放过一个可疑名，不误杀一个正确术语名。

### 输入

待判名字清单（每条：名字 + 被点字符）：
- 名字:「求和公式」
  被点字符:「和」
- 名字:「双进程与窗口」
  被点字符:「与」

## 输出契约（硬约束）

只输出一个 json 对象，不要解释、不要寒暄、不要加代码围栏。对象形如：

{"verdicts": [{"name": "名字原样", "bundle": true, "reason": "一句话理由"}, {"name": "另一个名字", "bundle": false, "reason": "一句话理由"}]}

- 每个输入名字恰好一条输出，`name` 逐字照抄输入的名字。
- `bundle` 为布尔：true = 多个主题捆绑；false = 单一主题术语。
- `reason` 非空，一句话说明判断依据。
