# w3: 核验 kind 扩展（高数采样核验）

**What to build:** claim kind 扩到 equation/inequality/derivative/integral/limit/
ode，**全部用数值方法核验，不引入 CAS**：导数 = 数值差分在采样点比对、积分 =
辛普森/梯形采样、极限 = 逼近点采样、ODE = 解函数代入残差采样、方程/不等式 =
采样点判定。手写求值器按需扩算子。

## 设计边界（用户拍板方向，全文见记忆 learning-verification-roadmap）

- 采样核验检测「生成错误」（0.7 vs 0.5 类非对抗错误）几乎必中；够不着的 =
  符号化简美观性（是否化到最简）与纯证明步骤链——明确非目标，留 v3 决策门
  （sympy sidecar，带 python 运行时成本）。
- **实现第一步 = 翻译质量抽验**：高数课程里模型把 ∫/d/dx 表达式翻译成 claim
  的可靠性未验证——先真机抽验翻译质量，再定 kind 粒度（过细的 kind 翻译失败
  率会吃掉核验收益）。

## 消费方

- 高等数学/物理/工程类课程的例题与推导步骤（生成侧打回自修改，同 w1 语义）。
- 若 w2 的多步批改已落地，微积分题的逐步核验直接受益。

## 实施要点

- [ ] 翻译质量抽验（前置）：真机生成 1–2 门含微积分例题的课程，人工+工具对照
      模型产出的 claim JSON 正确率，据实定 kind 设计。
- [ ] 求值器扩展：数值微分/积分/极限/残差算子（纯 Rust，采样点数与容差进
      claim）。
- [ ] 红绿样：含三角/指数/对数的导数核对（如 d/dx sin x = cos x 采样比对）、
      定积分（如 ∫₀¹ x² = 1/3）、ODE 解残差（如 y=e^x 满足 y′=y）；奇点/
      发散边界如实报「无法数值核验」而非误判。

## 验收

- `cargo test -p nomifun-learning` 全绿；fmt；零迁移。
- 真机判据：一门含微积分例题的课程生成，核验调用与 math_verify 读数在场；
  抽验的翻译质量问题如实记档。

## 非目标

- 符号化简/最简形式判定；证明步骤链推理核验（v3 决策门）；
- 几何图形核验；统计推断类断言（抽样模拟可作为后续候选）。
