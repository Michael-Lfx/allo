# 云模型目录生命周期与登录契约

- 最后维护：2026-08-24（元数据维护，未重写结论；核对基准 commit `d791691c6`）
- 日期：2026-08-06
- 状态：决策记录
- 范围：Flowy 内建云 Provider 的模型目录同步、登录完成后的模型恢复，以及本地会话和默认模型引用

## 决策摘要

1. 远端目录是 Flowy 内建 Provider 的本地投影，不是用户手工编辑的模型注册表。
2. `login_continue` 只完成认证和身份确认；模型同步由前端模型环境协调器显式执行。
3. 历史会话和用户默认模型是独立引用，目录变化不能静默改写它们。
4. Provider membership 与内建模型能力档案必须在同一个 SQLite 事务中发布；同步失败时保留上一次完整状态。

## 远端模型删除与重新上架

成功取得新的远端目录后，内建 Provider 的 membership 采用物理投影更新：不在新目录中的
`provider_models` 行会被移除。这样 resolver 不会继续把已经下架的模型当作可用模型，也不需要
新增数据库迁移或维护第二套“软下架”状态。

这不等于删除用户数据：

- 历史会话保存自己的 Provider/model 引用和消息内容，不由目录同步重写；
- `nomi.defaultModel` 失效时保留原值，不自动替换成第一个模型；
- 例外是运维关闭 `NOMIFUN_ENABLE_FREE_MODELS` 后，指向保留的
  `nomifun-free-model` 的活动配置会在 Flowy Cloud 目录同步成功后，按能力迁移到当前可用的
  Cloud 模型；这只修改未来运行所需的活动配置，不修改历史会话、消息或模型快照；
- 如果没有兼容的 Cloud 模型，可选配置会被清除，必需配置保留为不可执行状态，等待下一次成功同步，
  不会写入一个不兼容的聊天模型；
- 选择器可以根据引用未出现在当前目录这一事实显示“不可用”，但只有用户显式选择新模型时才写入新的默认值或会话绑定；
- 同一 Provider 下同一 canonical model id 之后重新上架时，新的目录行可以恢复可用；不会把旧 id 自动猜测或迁移到相似名称。

因此，目录同步的删除语义是“从当前可用目录移除”，不是“清理历史引用”。

## 登录完成与模型同步

`POST /api/cloud/login/continue` 的成功响应表示认证成功和身份可查询，不承诺本地模型目录
已经刷新。前端在确认账号后按固定顺序执行：

```text
同步云目录 → 刷新 Provider SWR → task resolver → 校验持久化默认模型
```

当前不增加 `model_sync_required` 字段：该阶段已经有明确的 `/api/cloud/sync-models` 入口和
前端 `ModelEnvironmentState`。如果未来服务端需要表达“认证成功但必须同步”的跨客户端契约，
应先新增版本化响应字段和所有客户端的兼容策略，再改变 `login_continue` 的 wire contract。

同步失败不会清除已确认的认证，也不会禁用用户自建 Provider。存在至少一个 resolver 可用
模型时进入降级状态并允许继续聊天；resolver 返回零模型或失败时只阻止发送，设置页、日志和
退出登录仍保持可达。

## 历史会话与默认模型

- 新对话恢复有效的 `nomi.defaultModel`；默认值格式错误、缺失或不在 resolver 结果中时，原值
  保留，发送前要求用户显式选择模型。
- 已有会话的绑定失效时，只有持久化默认模型被 resolver 确认为可用，才允许自动修复到该默认
  模型；自动修复不得写入或替换全局默认值。
- 持久化默认模型也失效时，不自动回退、不自动选择第一个模型，用户显式选择后同时更新会话
  绑定和默认值。

## 原子性边界

云同步会在同一 SQLite 事务中完成 Provider 行、membership 和内建 inferred profile 的发布。
档案同步的开始、中途或提交前故障都必须回滚整个目录更新；上一次完整目录继续作为缓存使用。
用户编辑过的 profile（非 `tasks=[]` 且 `source=inferred`）不会被云目录同步覆盖。

该原子性保证只针对当前 SQLite 实现。自定义 repository 实现若使用兼容 fallback，仍必须保持
幂等、保留用户档案，并在无法提供跨表原子性时显式报告失败；不得把部分结果当作同步成功。
