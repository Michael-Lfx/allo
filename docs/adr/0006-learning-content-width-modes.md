# ADR-0006: 学习模块的内容宽度双模式，余宽交给结构而非更长的文字行

Status: Accepted

Date: 2026-09-14

## Context

宽屏上学习模块的内容列居中限宽（课程列表与大纲工作区 1200px、学习图 1400px），
两侧留下大片空白；课时正文另有 760px 的行宽上限（`CourseWorkspace.tsx` 的
`max-w-760px`，注释写明是刻意的连续阅读保护）。三处留白叠加后，1920px 视口下
单侧可达约 360px。

诉求是「基本占满页面」。但「铺满」与「长文可读」直接冲突：中文长文行宽超过约
45 个汉字就开始跳行，把正文一路拉到 1300px（≈80 汉字/行）等于用可读性换视觉。

## Decision

**引入用户可切换的两种呈现模式（Standard / Wide），并把余宽交给结构与边框承担，
而不是交给更长的文字行。**

- 满宽布局去掉内容列的限宽，让内容撑满 `.app-page-shell` 的内边距；`.app-page-shell`
  自身的 40px 左右内边距保留——它是内容不贴窗口边的最后一层保护，且被设置页、
  能力中心、评测、账单共用，不在本次范围内。
- 课时阅读区在满宽布局下长出边框与内边距，成为**占满整行的面板**；正文行宽只从
  760px 放宽到 1040px（≈65 汉字/行）。这样页面左右看不出空洞，长文也不跳行。
- 大纲栏随视口三档放大（CSS 宽度 280 / 340 / 420px，content-box 实际占位约
  306 / 366 / 446px），把宽屏余量更多地让给常被截断的课时标题。
- 三个渲染面（课程列表、大纲工作区、学习图工作区）共用**一个**偏好键
  `learning.wideContent`，切一次整体生效，不出现「列表宽了、点进课程又缩回去」。
  宽度类名集中在 `pages/learning/layout.ts`，避免三面各自漂移。

## Considered Options

- **正文不设上限（真铺满）**：用户明确看过后放弃。留白最少，代价是宽屏行宽
  1200px 以上。
- **只抬列宽上限、正文保持裸文本**：改动最小，但文字右侧到页壳边距之间仍是真正的
  空白页——原诉求不会消失。
- **正文上限 1040px vs 1200px**：选了 1040。1200 更接近铺满，但已经把可读性让出去
  一截；1040 是「明显变宽、阅读还不难受」的位置。
- **做成全局能力（所有 `.app-page-shell` 页面共享）**：被否。作用域超出诉求，且要么
  改共享 CSS 波及全仓，要么给每个模块的调用点都加参数。

## Consequences

- 满宽布局下，只要阅读面板的内宽不超过 1040px（约 1810px 视口以下），正文就把面板
  填满，没有余白；之后每加宽视口，余白才按比例出现（1920px 视口每侧约 55px，2560px
  每侧约 375px，且是居中留白）。这是 1040px 上限的必然结果，不是 bug；要消掉它只能
  牺牲行宽。
- 大纲栏的宽度类是 **content-box** 语义：本仓库没有全局 `border-box` 重置，而该栏带
  `p-12px` 与 1px 边框，所以 280/340/420px 的实际占位约为 306/366/446px。标准布局的
  264px 口径相同，两侧一致；不要给其中一侧单独加 `box-border`。
- 三处留白来源（页壳内边距 / 列宽上限 / 正文行宽上限）从「读三个文件才知道」变成
  `layout.ts` 里的一张表。后续新增学习视图必须从这张表取类名，不得自行写死限宽。
- 偏好在窄窗口（<768px）下是无操作：限宽本来就不生效，页壳内边距已降到 16px。
