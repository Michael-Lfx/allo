# ADR-0016: 持久化演进纪律——信封版本、懒再生、发布前折叠

Status: Accepted

Date: 2026-11-02

## Context

学习域十几处 JSON 文档列无版本，格式只能靠 `serde(default)` 单向兼容（能加字段，不能改
语义/删字段）；LLM 产物本可再生成却被当死数据写迁移；分支上未发布迁移段积到 20 文件
810 行，且与 main 的 069 撞号。上线后这些结构全部冻结。

## Decision

三条纪律：

1. **学习者状态（不可再生产物）走扁平 version 信封**：落库 JSON 文档列写侧恒打
   `version`（与载荷键并列，同 `course_source_plan_json` / `structure_json` 先例），读侧
   未知版本显式降级、禁止猜形；历史裸对象视为 v0 读通、不回填。
2. **可再生产物不写迁移**：格式演进 = bump `format_version` + 打开时提示、用户显式触发的
   懒再生（走既有按需生成/重写/重建路径）；被学习者接管（ADR-0007）的节退出自动再生。
3. **发布前折叠**：每次发布前把未发布迁移段折叠为单一净形基线——未发布表直接建终态
   （消掉链内建-改-删折腾），已发布表的数据变换逐字保留并按原序排列；已发布迁移永不
   折叠、永不改动。

## Consequences

- dev 库在折叠后迁移谱系非前缀、启动即拒：`bun run reset:dev` 重建；smoke 临时库不受影响。
- 跨版本备份还原本就 fail-closed（`validate_current_migration_lineage` 要求 Current 谱系），
  本纪律不改变还原面。
- 基线文件是发布前一切 schema 变更的唯一落点，迁移票串行编辑；一次性等价校验
  （旧链 vs 新基线，schema 与种子数据逐项相等）是折叠票的验收硬门。
