# d4: 学习节点命名去模板化（生长提示词）

**What to build:** 现网学习节点标题清一色「用X认出Y：Z」类比句式（用团购券认出
看涨期权 / 用保价回收认出看跌期权 / 用留货优先券认出权利金 / 用预售锁价认出期
权行权价 / 用租房押金认出保证金……全是消费场景类比）。正常课程不这么命名。
改 `COACH_SYSTEM`：标题以学科内容本身命名；日常经验类比只活在 purpose 与正文
（它们本就是 intent/scope/purpose 的职责，标题不得承载）；配套句式软提示
（warn 通道，非阻断）。

## 法证证据（2026-11-10 实码核实）

- 提示词：`crates/backend/nomifun-learning/src/learning_graph/mod.rs:494`
  `COACH_SYSTEM`：
  - :499 title 字段说明只写「动作句：解/求/证明/推导/构造/比较/应用/辨析…」
    ——无命名口径约束，类比句式不受限；
  - :500 purpose「练什么 + 从哪段课程外日常经验切入（座位表定位/给物品分类/
    分食物看温度一类生活场景）；找不到日常经验切口的节点不合格」与 :528 节点
    纪律「每个节点的 purpose 必须点出从哪段日常经验引入——但切口只是引入方
    式，节点内容永远是学科概念」——类比被强制且只约束了 purpose，模型把它泄
    进标题；
  - :501-502 intent/scope 字段就是教学意图的正向承载（用户问的「教学意图的相
    关字段」即此）——标题不需要替它干活。
- 首批用户提示（`mod.rs` 首批纪律块，:671 一带）也只写「动作句 + 单一行为单
  元」——首批正是病历截图的节点来源。
- 软提示通道：`mod.rs:440-481` y01 名字形态点名（`ng.mints.name_hint`，warn 不
  阻断、不进重试反馈），现查「并列字/分隔符」；句式检测同通道挂靠。
- 评审契约 `growth_contract.rs:47` `REVIEW_FIELDS` 含 title（评审面不动）。
- 真机病历：2026-11-09 期权课五节点全中同一句式；首批与手动补批同一来源
  （COACH_SYSTEM 唯一）。

## 实施要点

- [x] :499 title 字段说明改写：动作句要求保留 + **以学科内容本身命名**（主题
      + 动作/角度）+ 类比不得进标题、指向【节点纪律】。
- [x] :528 节点纪律补：**切口与类比只出现在 purpose 与正文，不得进标题**；标
      题以学科内容本身命名（示例「看涨期权：买方的权利与到期损益」）；禁止
      「用X认出/理解Y」「从X看Y」句式与统一模板；点明「正常课程的目录里找
      不到这种名字」。
- [x] 首批纪律块（用户提示）同步补「标题以学科内容本身命名，日常经验类比只
      写进 purpose、不得进标题」——原「常识」条款保留（施工中一度误删，自查
      恢复）。
- [x] 句式软提示：`title_template_hint`——以「用」开头且含 认出/看懂/理解，
      或以「从」开头且含「看」→ `ng.title.template` warn（非阻断、不进重试
      反馈，y01 同口径）；命中面刻意收窄（宁漏报不误报：学科动作句「用换手
      率判断热度」不中）。挂在 validate_batch 的节点标题循环。
- [x] 自检：与 :529 声明面条款、:533「标题相应只写一个动作」、:535「标题不得
      完全相同」无冲突；`growth_contract` title 校验（TITLE_MAX_CHARS / 批内
      唯一）不动。
