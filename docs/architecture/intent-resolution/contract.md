# Intent Resolution Contract

This document is the authoritative domain and interface contract for the proposed
`nomifun-intent` module. Types are illustrative Rust shapes; implementation has not been approved.

## Public Interface

The module presents one interface:

```rust
#[async_trait]
pub trait IntentResolver: Send + Sync {
    async fn resolve(
        &self,
        request: ResolveIntentRequest<'_>,
    ) -> Result<IntentResolution, IntentResolutionError>;
}

pub struct ResolveIntentRequest<'a> {
    pub input: ResolveIntentInput,
    pub evidence: &'a dyn IntentEvidenceBroker,
}
```

Callers do not coordinate the deterministic prepass, semantic interpreter, evidence admission,
refinement pass, or invariant validator. Those remain implementation details behind `resolve`.

`NoEvidenceBroker` is used when no evidence operation is available.

## Input

```rust
pub struct ResolveIntentInput {
    pub utterance: String,
    pub source: IntentSource,
    pub surface: IntentSurface,
    pub attachments: Vec<InputReference>,
    pub context: IntentContextSnapshot,
    pub previous_resolution: Option<ResolutionSnapshot>,
    pub mode: ResolutionMode,
}

pub struct IntentContextSnapshot {
    pub conversation: Option<ConversationSummary>,
    pub recent_messages: Vec<MessageSummary>,
    pub facts: Vec<ContextFact>,
    pub explicit_target: Option<TargetCandidate>,
    pub pending_interaction: Option<PendingInteractionSummary>,
    pub target_candidates: Vec<TargetCandidate>,
}
```

Input constraints:

- recent messages and facts have hard item and character limits;
- target candidates are validated by the caller;
- no Runtime handle, authority token, credential, arbitrary tool schema, or full tool trace is accepted;
- a string generated by the model cannot be used to access a downstream object;
- missing context and missing evidence capability are valid inputs.

## Utterance Segmentation

The current utterance is not uniformly a current instruction. The resolver first classifies spans:

```rust
pub struct UtteranceSegment {
    pub range: TextRange,
    pub role: UtteranceRole,
}

pub enum UtteranceRole {
    DirectInstruction,
    QuotedContent,
    Example,
    ExternalData,
    Hypothetical,
    Commentary,
}
```

Only `DirectInstruction` may establish a current user instruction. Quoted or pasted content remains data
even when it contains imperative language.

## Claim Provenance and Commitment

Origin and user commitment are independent:

```rust
pub enum ClaimOrigin {
    CurrentUtterance,
    HistoricalUserStatement,
    HistoricalAssistantProposal,
    ToolObservation,
    ProjectDocument,
    MemoryRecord,
    ExternalSource,
    ResolverInference,
}

pub struct Commitment {
    pub kind: CommitmentKind,
    pub scope: CommitmentScope,
}

pub enum CommitmentKind {
    Mention,
    Hypothesis,
    Preference,
    Selection,
    Confirmation,
    Instruction,
}

pub enum CommitmentScope {
    ExactClaim,
    OverallDirection,
    SelectedOption,
    CurrentTask,
    DurablePreference,
}
```

Examples:

```text
assistant proposes ten steps
+ user says "the direction is fine"
-> Confirmation + OverallDirection
-> the ten steps remain HistoricalAssistantProposal

user selects option B
-> Selection + SelectedOption
-> unselected options do not become user constraints
```

## Output

The public output has four top-level concerns:

```rust
pub struct IntentResolution {
    pub schema_version: IntentSchemaVersion,
    pub status: ResolutionStatus,
    pub intent: IntentBundle,
    pub suggestion: HandlingSuggestion,
    pub evidence: ResolutionEvidence,
}
```

### Resolution Status

```rust
pub enum ResolutionStatus {
    Sufficient,
    Provisional,
    InsufficientEvidence,
    InterpreterDegraded,
}
```

`Sufficient` means the available information is sufficient to form an advisory interpretation. It does
not mean the interpretation is guaranteed correct.

`Provisional` must not be consumed as an automatic routing or execution instruction.

### Compound Intent

```rust
pub struct IntentBundle {
    pub primary: IntentUnit,
    pub secondary: Vec<IntentUnit>,
    pub global_constraints: Vec<IntentConstraint>,
}

pub struct IntentUnit {
    pub sequence: u16,
    pub interaction: InteractionKind,
    pub work_relation: WorkRelation,
    pub intended_effect: IntendedEffectHint,
    pub output_mode: OutputModeHint,
    pub goal: Option<IntentClaim<GoalDraft>>,
    pub targets: Vec<IntentClaim<TargetHint>>,
    pub local_constraints: Vec<IntentConstraint>,
}
```

Intent units preserve utterance order. They are not a Goal graph, Plan, DAG, or executable task list.

### Mutually Exclusive Handling Suggestion

```rust
pub enum HandlingSuggestion {
    Respond,
    Discuss,
    Clarify {
        draft: ClarificationDraft,
    },
    ConsiderPlanning {
        blocking_gaps: Vec<MissingInformation>,
    },
    ConsiderAction,
    ControlIntentDetected,
    UnsupportedOrUnknown,
}
```

`HandlingSuggestion` is advisory. It is not a dispatch decision.

`TaskBrief`, formal Plan creation, Focus binding, approval, and capability selection are excluded from
the core contract.

### Evidence and Diagnostics

```rust
pub struct ResolutionEvidence {
    pub claims: Vec<ClaimEvidence>,
    pub information_needs: Vec<InformationNeed>,
    pub diagnostics: ResolutionDiagnostics,
}
```

Ordinary callers should need only `status`, `intent`, and `suggestion`. Evidence is retained for
explanation, evaluation, and auditing.

## Cross-field Invariants

The deterministic validator rejects or downgrades outputs that violate these rules:

- `Sufficient` cannot coexist with an unresolved required information need.
- `Clarify` contains exactly one highest-value question in P0.
- `Respond` cannot coexist with a blocking gap that changes the interpretation.
- a quoted, example, external-data, or hypothetical span cannot establish `Instruction`.
- a historical assistant proposal cannot establish a user `Selection`, `Confirmation`, or `Instruction`.
- `ControlIntentDetected` does not claim that a Runtime operation occurred.
- `ConsiderAction` does not contain approval or execution authority.
- targets without caller-validated or broker-returned logical references remain hints.
- `InterpreterDegraded` exposes only deterministic conclusions that passed validation.
- diagnostics never contain credentials or unrestricted raw tool output.

## Error Semantics

```rust
pub enum IntentResolutionError {
    InvalidInput,
    InterpreterUnavailable,
    Timeout,
    InvalidStructuredOutput,
    InvalidEvidenceContract,
    Internal,
}
```

Ordinary evidence outcomes such as unavailable, denied, not found, truncated, or budget exhausted are
not fatal resolver errors. They produce diagnostics and an unresolved information need.

The caller owns fallback. Ignoring an error and preserving the existing message path is always valid.

## Explicit Exclusions

The contract contains no:

- message admission or send disposition;
- Conversation persistence;
- Task, Goal, Plan, or AgentExecution creation;
- Focus attachment;
- Provider or model selection;
- capability lease;
- approval result;
- Runtime, Thread, or session identity;
- arbitrary tool name;
- filesystem path or SQL;
- write, send, publish, cancel, install, or execute operation.
