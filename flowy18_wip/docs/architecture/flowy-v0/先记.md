### 5.11 超时要区分「对方没开始」与「对方在跑但慢」

一刀切的超时会把「平台迟迟不启动」和「任务很大跑得久」混成同一件事，处理方式却是相反的。

原文的区分：

1. 等检查超过 10 分钟仍没有新运行 → 判为**平台没开始**，触发自救（转草稿再转正式，只自救一次，并从这次重新计时）。
2. **必需任务已经创建、在排队或执行 → 继续等**，不因运行时间长而自救。

**「等太久」不是判据，「有没有在动」才是。**

### 5.14 Trigger 与批处理：Router 是一批一批醒的

**它不是「收到一条消息就醒」，是「一批 Trigger 一起醒」。**

三类 Trigger：

1. **人说话**
2. **Worker 汇报** —— 完成、失败、被停、超时，四种都算
3. **定时或外部事件**

**批处理怎么成立**：Router 一轮推理期间到达的 Trigger 先积压，下一轮合并注入一次。因为它每步是「长输入、短输出」，Prefill 阶段并行计算，单次请求耗时的增长远慢于批次大小。

DSH 压力测试：到达速率从每分钟 1 条升到 40 条，batch 从 1.0 升到 2.8，单次请求只从 2.5 秒增到 3.9 秒——**单个决定分摊的推理时间从 6.4 秒降到 1.6 秒**。

**这条对我们为什么重要**：多 loop 全双工之后，Worker 汇报会集中爆发（几个同时完成）。没有 batching，Router 要醒 N 次；有了它，醒一次。

### 7.3 自进化的五级与边界

| 级别 | 改什么 | 我们做不做 |
| --- | --- | --- |
| L0 | 记忆（事实） | 做 |
| L1 | 策略 / 规则 | 做（同类线索两次才升级） |
| L2 | skill 文本 | 做，但要配评测集 ＋ 五道门禁 |
| L3 | 自己的代码 | **不做** |
| L4 | 改进方法本身 | 不做 |

**五道门禁**：测试全绿 / 尺寸硬上限 / 缓存兼容 / 语义不漂移 / 只走 PR 不直提。

**一条底线**：没有评测集就不做自进化。**一条硬边界**：agent 不许改 Skill 文件。

### 8.7 告警抑制：首次报、持续静、恢复报

AutoLoop 在网站检查场景里的做法，是抑制告警的正解：

1. **首次失败** → 发通知 ＋ 排查事件
2. **持续失败** → 保持安静
3. **恢复** → 结案 ＋ 发恢复事件
4. **人手动关掉了未恢复的卡、之后仍失败** → **重新报告**

第 4 条最关键：手动结案不能变成永久静音。

**一条统计边界**：只有当前身份可读的数据参与汇总，**不把「看不见」当成「没提交」**。否则权限一收紧，报表就开始撒谎。

### 8.8 送达语义：卡片怎么才算送到

**卡片内容创建后不再变，只有状态会变。** 所以更新一张卡不是"发新消息"，而是"改那条"。

一条完整的投递链：

1. 通道来领卡片（阻塞等待）
2. 有 `ref` 就改那条，没有就发新消息
3. **必须回报「已送达」** —— 没回报的，一分钟后重新派给它
4. 发不出去就回报「失败」：重试间隔逐次拉长，**一小时后放弃**，卡片仍然开着等人处理

**三条容易做错的细节**

1. **支持幂等键的平台，发新消息只用卡片编号，不带版本号。** 带上版本号反而会重复 —— 版本号是"改哪一条"用的，不是"这是第几条"。
2. **平台改不动已结束的卡片时，才另发一条**，那一条才带版本号。
3. **还没送到、但已经被解决了的卡片，不再打扰用户。** `fyi` 类在创建后 24 小时内仍可投递。

### 8.9 回答的三重校验

一次回答要被接受，必须同时满足三条：

1. **只认第一次** —— 后到的回答直接丢弃，不覆盖。
2. **回答者在这个通道的授权名单里。**
3. **引用的送达凭证必须和那张卡实际送达的那次一致。**

第 3 条最容易被忽略，它防的是**「拿旧卡片的凭证去答新卡片」**。只校验"这张卡存在"是不够的。

**链接型卡片的边界要说清**

有些平台只能发文字、发不了按钮，这时给一个链接打开表单页。代价是：**谁拿到链接谁就能答**。

所以：

1. 链接只能发给允许收链接的通道；
2. 链接有有效期（参考值：7 天），过期后连卡片内容也不再显示；
3. **能发按钮、能收回调的通道优先用按钮** —— 身份由平台核验，比链接安全；
4. 本机地址的链接手机打不开，要手机批就得让服务有可达地址。
