# 目标（Goals）

**目标（Goals）** 让 Nomi 会话变成一个自驱动循环：你只需陈述一次目标，之后
每一轮智能体回复结束时，一个轻量的**评审器（judge）**都会对照该目标检查最新
回复。若目标尚未完成，循环会自动向智能体注入一条继续提示——在有界的回合预算
内——让长任务持续推进，无需你反复催促。

Goals 与 [AutoWork](autowork-requirements.zh.md) 和
[IDMM](intelligent-decision.zh.md) 天然互补：AutoWork 决定*做什么*，IDMM 保证
每一轮*不卡死*，而目标则让会话始终对准*同一个结果*，直到它被可验证地达成。

> 目标按会话生效，目前仅支持 **Nomi** 会话。下文所有操作都通过聊天输入框的
> 斜杠命令完成；同一组操作也通过 HTTP API 暴露
> （`POST /api/conversations/{id}/goal`）。

## 快速上手

```text
/goal 完成 CSV 导出功能，并让 `bun test` 全部通过
```

仅此而已。智能体照常工作；它每完成一轮，评审器就读取回复并给出三种裁决之一：

- **done**——目标已满足（或可证明被阻塞）；循环停止。
- **continue**——未完成，且存在明确的下一步；循环注入继续提示，智能体再跑
  一轮。
- **wait**——未完成，但下一步是等待某个异步事件（构建、后台会话、限流冷却）；
  循环停靠在[等待屏障](#等待屏障)上，不消耗回合。

输入框上方的状态卡片会显示目标、回合预算进度条、暂停/继续/清除按钮，以及
（存在时的）子目标、完成合约与当前等待屏障。

## `/goal` 命令

| 命令 | 作用 |
| --- | --- |
| `/goal <目标>` | 设置（或替换）目标并启动循环。 |
| `/goal status` | 查看当前目标、裁决、预算与屏障。 |
| `/goal show` | `status` 的别名；提示中会额外列出合约各字段。 |
| `/goal pause` | 暂停循环。会丢弃等待屏障；子目标保留。 |
| `/goal resume` | 恢复已暂停的目标。回合预算与失败计数器全部重新开始，过期屏障被丢弃。 |
| `/goal clear` | 彻底结束目标——目标文本、子目标、合约与屏障全部清除。 |
| `/goal draft [目标]` | 让模型基于给定（或当前）目标起草一份[完成合约](#完成合约)并立即应用。 |
| `/goal wait <pid>` | 手动让目标停靠等待进程 `pid` 退出。覆盖任何评审器设置的屏障。 |
| `/goal unwait` | 解除当前等待屏障，回到正常评审。 |

说明：

- `/goal draft` 是一次 LLM 调用，需要几秒钟；UI 会先显示加载提示，完成后逐
  字段展示起草的合约。
- `/goal wait` 会在本地直接拒绝 pid `0` 及非数字输入；后端也会拒绝对已完成
  或已清除的目标设置等待。
- 对未处于等待中的目标执行 `/goal unwait` 会报错（"The goal is not
  waiting"）。

## `/subgoal` 命令

子目标是你在循环中途追加的验收标准。评审器必须为**每一条**子目标找到具体证
据，才允许给出 *done*。

| 命令 | 作用 |
| --- | --- |
| `/subgoal <文本>` 或 `/subgoal add <文本>` | 追加一条标准。 |
| `/subgoal list` | 列出当前标准。 |
| `/subgoal remove <n>` | 删除第 `n` 条（从 1 开始）。 |
| `/subgoal clear` | 清空全部标准。 |

子目标在 `pause`/`resume` 之间保留；只有 `/goal clear` 会连同目标一起删除。

## 回合预算与评审器

每次自动继续消耗一个单位的**回合预算**（默认 **8**，可通过 API 的
`max_turns` 字段按请求配置，取值收敛到 1..100）。预算耗尽后循环只是停止继续
——目标仍然可见，`/goal resume` 会以全新预算重启。停靠在屏障上**不**消耗预算，
且预算窗口在新的后端进程中重新开始。

评审器本身刻意做得便宜且安全：

- 它是一次**一次性旁路请求**，跑在会话的主模型上——不带工具、不带思考，也
  从不触碰会话历史与系统提示词，因此主提示词缓存保持完好。
- 它看到的是目标、子目标/合约、智能体最近回复的有界尾部，以及在跑后台进程
  的快照，并且必须以严格的单行 JSON 给出裁决。
- 它**失败即放行（fail-open），绝不假 done**：解析不了或调用失败一律降级为
  *continue*。连续的解析/传输失败会分别触发断路器，把目标暂停而不是无限循环。

*你*输入的消息始终优先：循环会让位于用户输入，而不是与其抢跑。

## 等待屏障

*wait* 裁决（或手动 `/goal wait`）会把目标停靠在三种屏障之一上：

| 屏障 | 设置方 | 释放条件 |
| --- | --- | --- |
| **会话**（`wait_on_session`） | 评审器 | 后台会话退出，或其 watch 触发器命中 |
| **进程**（`wait_on_pid`） | 评审器或 `/goal wait <pid>` | 进程退出 |
| **时间**（`wait_for_seconds`） | 评审器 | 到达截止时刻 |

多种屏障同时相关时，实际优先级为**会话 > 进程 > 时间**。UI 会显示屏障行，并
附带一个内联的**解除等待**按钮。

释放是**懒惰的**：屏障满足的那一瞬间不会有任何东西唤醒循环。而是在下一个评
估点（循环下次本要评审时），运行时检查屏障——若截止已过、进程已死或会话已结
束，就静默清除屏障，并在同一次调用里恢复正常评审。这也是为什么倒计时归零时
显示的是"将在下一回合恢复"，而不是假装循环已经在跑。

进程/会话存活性通过宿主注入的探针检查，且**失败即放行**：无法明确确认存活
时，屏障即释放。过期屏障永远不会卡死循环；最坏情况只是提前一轮恢复，这是安
全的。

## 完成合约

**合约**把"评审器目测回复"替换为一份显式、可审阅的完成定义。它有五个字段，
均为可选字符串：

| 字段 | 含义 |
| --- | --- |
| `outcome` | 完成时必须成立的唯一终态。 |
| `verification` | **证明**该终态的具体测试/命令/产物。存在合约时，这是评审器判定完成的唯一权威标准。 |
| `constraints` | 过程中必须遵守的规则。 |
| `boundaries` | 明确不在范围内的内容。 |
| `stop_when` | 智能体应停下来汇报而非继续硬推的条件（命中即视为 *done，原因为阻塞*）。 |

用 `/goal draft` 设置一份（模型基于目标起草并立即应用——可在状态卡片的合约
折叠区审阅），或通过 API 的 `set_contract` action 以编程方式设置。发送一份五
字段全空的合约即清除合约。合约存在时追加的子目标会并入合约，作为额外标准。

## 配置

Goals 没有配置文件入口。唯一的旋钮是回合预算：随 API 的 `set` action 传入
`max_turns`（默认 **8**，收敛到 1..100）。斜杠命令始终使用默认值。

## 持久化

目标状态（目标文本、状态、预算、子目标、合约、裁决）按会话持久化，重启后仍
在。描述*一次运行*的计数器——自动继续窗口与断路器计数——则刻意随新进程重新
开始。

## 渊源与和 hermes 的差异

目标循环移植自 hermes 智能体的 goals 功能（其本身受"Ralph loop"模式启发）。
行为与 hermes 语义一致——评审提示词、三裁决契约、屏障懒释放与失败放行探针均
为直接移植——但有以下刻意差异：

- 默认回合预算为 **8**（hermes 为 20），且通过 API 按请求设置，而非
  `config.yaml`。
- 合约只能通过 `/goal draft` 或 API 设置——目标文本中没有内联的
  `field: value` 合约语法。
- `/goal wait <pid>` 不接受自由文本的原因参数。
- 评审器跑在会话的主模型上；没有独立的辅助评审模型设置。
- Goals 仅在 Nomi 会话中可用。
