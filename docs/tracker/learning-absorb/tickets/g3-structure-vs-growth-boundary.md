## Question

learnhub 铁律：结构对生长**不供内容、不做判定、不与概念建立任何连接**；教练参考材料 =
「全量块摊开」（呈现序 = 难度档/前置链深/主干序，行格式带「无前置」结构布尔），纯结构事实、
不裁剪候选面、不限批范围——教练可围绕参考装箱也可自拟。

allo 现状的对应面需要逐项裁决：

1. **教练上下文**：现有 `CoachContext::render`（学习目标/范围参考/罗盘/首级判据/就绪读数/
   花名册/已教概念账/终点锚/覆盖读数/行为摘要/登记表切片）里，终点锚与罗盘已随 g1 裁决
   删除；剩余问题是结构参考材料（全量块摊开，learnhub `reference.rs` 形态）取代哪些现有块
   （范围参考/首级判据/入口域盘点）、覆盖读数降为纯展示后是否仍进教练上下文。
2. **既有结构门 vs learnhub 铁律**：`validate_batch` 的就绪即发布（assumes 必须被全局已教账
   覆盖）正是 learnhub「概念侧两层门」的同源实现，保留无疑；但 `validate_batch_depth`
   深度水位门（最高难度 ≤ 批次数 + 2、关键词虚标堵漏）与 structure.blocks 的 stage
   （入门|进阶|高级）是什么关系——水位门是否退役交给结构参考、还是保留为双保险
   （learnhub 判「档位比较门禁是精度剧场」，但那是在结构仅参考的前提下）。
3. **终点保护条款**：`validate_batch` 里终点相关条款随 g1 裁决调整或删除。
4. **入口域盘点**：首批专享的 `survey_entry_domains` 与前置地形（门口 G 判据）功能重叠，
   取舍随 g2 产物裁决。

明确清单，供实施票直接引用。
